### 与卡面/设计的三处对齐说明（都写进迁移头注释，不做事后解释）

1. **「11 张表」的口径**：卡面列了 10 个表名 + 「5 张基线表连带补齐」，按字面是 15 张、按标题是 11 张。
   W0 §2.1 的表清单是 **11 张**（本批 4 条迁移合计：V0137 七张 + V0138 一张 + V0139 三张），
   其中「5 张是基线补齐」。本卡按 **W0 的 7 张 + 卡面点名但 W0 留给批次1 的 6 张主数据** 落地，
   合计 13 张 —— 卡面点名的表**一张不缺**，也不自己造第 14 张。
2. **`serial_required` / `external_sn` 不在 V0137**：W0 §2.5 明确该列由 **V0138** 加。本迁移不抢这张卡的
   结构决策；种子用 `DO` 块按「列是否存在」条件标记一物一码物料，因此「只跑 V0137」与「V0137+V0138」
   两种顺序都正确（实测日志：`serial_required 列尚未创建（属 V0138），跳过一物一码标记`）。
   `external_sn` 在 `biz_material_serial`（V0138），同样不在本卡。
3. **状态列口径**（卡面要求 VARCHAR）：**业务单据状态用 VARCHAR + CHECK 枚举**
   （`biz_purchase_order.status` VARCHAR(24)、`biz_accounting_period.status` VARCHAR(16)）；
   **主数据启用位仍是 SMALLINT 1/0**（`biz_unit/warehouse/material/supplier/account/location/seq.status`）。
   两者是不同语义，批次1 §2.1 原样照抄，未擅自统一。反例 5 专门验证 VARCHAR 状态列的 CHECK 真的会拦。

## 5. 验收 ⑤：索引生效（20 万行模拟）

```
总行数: 200002
目标子树行数（LIKE '/d13700ff-…-0001/%'）: 100
表大小: 84 MB
库 collation: en_US.UTF-8
```

**⑤-a 有 `text_pattern_ops` 索引：**

```
->  Index Only Scan using idx_biz_warehouse_path_pattern on biz_warehouse (actual time=0.032..0.067 rows=100.00 loops=1)
      Index Cond: ((warehouse_path ~>=~ '/d13700ff-0000-4000-8000-000000000001/'::text) AND (warehouse_path ~<~ '/d13700ff-0000-4000-8000-0000000000010'::text))
      Filter: ((warehouse_path)::text ~~ '/d13700ff-…-0001/%'::text)
      Heap Fetches: 100
Execution Time: 0.114 ms
```

**⑤-b 去掉 pattern 索引（同一查询、同一数据）：**

```
->  Parallel Seq Scan on biz_warehouse (actual time=5.667..9.364 rows=33.33 loops=3)
      Filter: ((warehouse_path)::text ~~ '/d13700ff-…-0001/%'::text)
      Rows Removed by Filter: 66634
Execution Time: 15.442 ms
```

**[PASS]** 0.114 ms（Index Only Scan，`Index Cond` 有 `~>=~ / ~<~` 边界）vs 15.442 ms（全表顺序扫描）→ **135×**。
实测库的 collation 是 `en_US.UTF-8`（不是 W0 文档写的 `zh_CN.UTF-8`），默认 btree 一样推不出 LIKE 前缀边界
（表里同时存在 `idx_biz_warehouse_path` 默认 btree，⑤-b 里它完全没被考虑），所以 `text_pattern_ops` 这条索引是硬需求。

**⑤-c 复原索引**（与迁移定义一字不差）后复核：`CREATE INDEX idx_biz_warehouse_path_pattern … (warehouse_path text_pattern_ops)`，
查询回到 0.108 ms。

**⑤-d 子树两种写法**：物化路径 `LIKE '/祖先/%'` **0.097 ms**；等价递归 CTE **0.191 ms**（100 个后代、101 次 index scan）。
