## 一、这个功能干什么

把「跟谁签、签多少、什么时候开始、什么时候结束」落成一张可用于**内控与付款**的单据：
合同通过审批后变成「已签订」，采购单 / 销售单才能引用它并往下执行；到期提醒、履约金额、
在途单据统计都挂在这张单上。

**一句话边界**：合同管**承诺**，不管**执行**。单据的收发货、开票、付款在各自的单据上，
合同只回答「这份承诺还在不在有效期内、还用掉多少」。

## 二、谁能用（角色 + 权限）

| 动作 | 权限码 | 说明 |
|---|---|---|
| 查看列表 / 详情 | `business:erp:contract:list` | 详情里额外下发 `can_edit` / `next_statuses` / `open_order_count` |
| 新建 | `business:erp:contract:create` | 只有草稿可建，取号 `HT-yyyyMMdd-000001` |
| 编辑 | `business:erp:contract:update` | **只有 `DRAFT` 可改**（其余状态 409 + `66016`） |
| 删除 | `business:erp:contract:delete` | 软删；被采购单引用时 409 + `66018` 并点名单号 |
| 状态流转 | `business:erp:contract:status` | 提交审批 / 登记签订 / 生效 / 归档 / 终止 |
| 跳过审批（异常口） | `business:erp:skip-approval` | 没有已发布流程时才可用，且理由 ≥10 字 |

`SUPER_ADMIN` 短路全部校验（开发 / 交付期用，生产按岗位配）。

## 三、乙方怎么建：**服务商 / 出租方都建在供应商档**

合同类型与乙方的对应关系是**单向、应用层强制**的（决策 **D1**，
`docs/合同类型开放口径-决策.md` §二）：

| 合同类型 | 乙方主档 | 乙方类型 `party_b_type` | 选谁 |
|---|---|---|---|
| `PURCHASE` 采购合同 | 供应商 | `SUPPLIER` | 卖货给我们的供应商 |
| `SALES` 销售合同 | 客户 | `CUSTOMER` | 买我们货的客户 |
| `SERVICE` 服务合同 | **供应商** | `SUPPLIER` | **服务商登记成供应商** |
| `LEASE` 租赁合同 | **供应商** | `SUPPLIER` | **出租方登记成供应商** |

要点（给业务同事看的版本）：

1. **系统里只有「客户」和「供应商」两种交易对手主档**，没有「服务商」「出租方」这种独立档；
2. 服务商 / 出租方一律**建在供应商档**（`biz_supplier`），原因：付款要用到的字段
   （应付科目、账期、信用额度、开票四件套）全在供应商档里，建独立档等于把这一整套重建一遍；
3. `SERVICE` / `LEASE` 传 `CUSTOMER` → **一律 400**（`66021`，「乙方不存在 / 类型不匹配」）；
   界面上乙方选择器会按合同类型换 label：采购→「乙方供应商」、服务→「乙方服务商」、
   租赁→「乙方出租方」、销售→「乙方客户」；
4. 代价（已知、不藏）：供应商列表和采购单的供应商下拉里会混进服务商 / 出租方 ——
   这是当前版本的取舍，后续若做供应商分类（`GOODS/SERVICE/LEASE/MIXED`）会再收窄。

## 四、状态怎么走（6 态）

```
DRAFT ──提交审批──▶ PENDING_APPROVAL ──审批通过──▶ SIGNED ──生效──▶ ACTIVE ──归档──▶ COMPLETED
  ▲                        │                                 │
  └──── 驳回 / 撤回 ◀───────┘                                 └──终止──▶ TERMINATED
```

| 状态 | 中文 | 能做什么 / 不能做什么 |
|---|---|---|
| `DRAFT` | 草稿 | 唯一可编辑的状态；不能直接签订（必须先提交审批） |
| `PENDING_APPROVAL` | 审批中 | 业务字段冻结；待办在审批人处 |
| `SIGNED` | 已签订 | 可被采购单 / 销售单引用；关键字段（乙方 / 金额 / 日期）冻结 |
| `ACTIVE` | 已生效 | 可被新单据引用；服务 / 租赁类开始算服务期 / 租期 |
| `COMPLETED` | 已归档 | **不再接新单**（终态） |
| `TERMINATED` | 已终止 | 不可撤销（终态）；原因写进状态日志与备注 |

**最常见的两个坑**

1. **归档的字是 `COMPLETED`，不是 `CLOSED`**。接口 `PATCH /status {"target_status":"CLOSED"}`
   会返回 **400 + 10001**（参数非法）。`CLOSED` 是采购单 / 销售单的状态，不是合同的。
2. **`COMPLETED` = 归档，不等于「履约完成」**。是否履行完要看详情里的
   `open_order_count`（未关闭下游单据数）是否为 0 —— 报表判「已履行」用它，别只看状态。

### 4.1 路径①：走审批中心（正常路径）

`提交审批 → 审批人在「审批待办」里通过 → 合同自动落「已签订」→ 点「生效」`。

### 4.2 路径②：登记签订（线下已签、系统补登记）

适用场景：纸质合同已经在会签 / 盖章，但流程没在系统里走完。

操作：`PATCH /business/erp/contract/{id}/status`，body `{"target_status":"SIGNED"}`。

**这条路径会做什么**（E2E07-FIX-4 ① 之后）：

- 合同直接落 `SIGNED`（保留原审批实例 id 作审计，详情仍显示 `FLW-…` 单号）；
- **同时在跑的审批实例被终止**：实例 `CANCELLED`、该审批的所有待办 `CANCELLED`、
  流程节点收口；合同状态日志写明「审批中心外登记签订：审批实例已终止（待办一并取消）」；
- 也就是说**登记签订之后，审批人那边的待办会消失** —— 这是设计意图：合同已经签了，
  再让人签一遍等于让一张已签合同被重判一次。

> 修改前的行为（问题原样）：合同已 `SIGNED`，审批实例仍 `PENDING`、待办仍挂着 ——
> 会签没走完时只剩「把剩余会签全签完」一条出口，没有审批权的人只能找工程师改库。

## 五、归档前提示：还有 N 张未关闭单据

**设计决策 E4**（`docs/architecture/ARCH-2-合同表数据模型与校验规则.md` §5.2、
`docs/architecture/合同与勾稽关系设计.md` §6.4 E4）：归档**不硬拦**在途单据 ——
终止或归档一份合同是常态，硬拦会把「已成立的业务承诺」卡死。

所以系统的做法是**提示但不拦**：

1. 详情页「履约情况」区一直显示：未关闭单据 **N 张** + 单号清单（数据源 = 详情接口
   `open_order_count` / `open_order_nos`）；
2. 点「归档（COMPLETED）」时，确认弹窗顶部出现黄色警示条：
   **「归档前请注意：这张合同仍有 N 张未关闭单据。归档后不再接新单，这些单据仍可继续执行到底。」**
   （列表页点归档也会显示 —— 列表行没有这个字段，前端会按需拉一次详情回填）；
3. N = 0 时**不显示**任何提示（别给用户与审计塞噪声）。

统计口径（与后端一致，不要自己重算）：

- 采购单未关闭 = `status NOT IN ('RECEIVED','CLOSED','CANCELLED')` 且未软删；
- 销售单未关闭 = `status NOT IN ('OUTBOUND','CLOSED','CANCELLED')` 且未软删。

## 六、常见错误怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「必须先提交审批」 | 草稿直接点签订 / 生效（409 + `66015`） | 先提交审批；线下已签走**路径②登记签订** |
| `target_status=CLOSED` → 400 + 10001 | 合同没有 `CLOSED` 这个状态 | 用 `COMPLETED`（归档） |
| 改单被拒（409 + `66016`） | 只有草稿可改 | 让审批驳回 / 用户撤回退回草稿后再改 |
| 删除被拒（409 + `66018`） | 合同被采购单引用 | 先处理（或关闭）引用的采购单 |
| 建服务 / 租赁合同报乙方类型不对（400 + `66021`） | 传了 `CUSTOMER` | 服务商 / 出租方建在**供应商档**，选 `SUPPLIER` |
| 提交审批 409 + `65020` | 没有已发布的 `contract_approve` 流程 | 让管理员发布流程；或 `skip-approval` + ≥10 字理由显式跳过 |
| 审批通过后合同还显示「审批中」 | 三个日期不齐，回调跳过回写 | 补齐 `sign_date/start_date/end_date`（草稿才能改） |

## 七、与哪些功能联动

| 联动对象 | 关系 |
|---|---|
| 采购单 / 销售单 | 合同 `SIGNED` / `ACTIVE` 时可选；单据上 `contract_id` 反查合同，金额计入「已执行」 |
| 审批中心（`flow`） | `contract_approve` 流程；待办、会签、审批意见都在那边 |
| 状态日志 `biz_status_log` | 每次状态流转一条（谁 / 何时 / 为什么），路径②会写「审批实例已终止」 |
| 附件（`biz_doc_attachment`） | 合同扫描件 / 补充协议，`biz_type=CONTRACT` |
| 到期提醒 | `reminder_contract`：临近 `end_date` 发通知 |
| 联动规则（`biz_linkage_rule`） | `CONTRACT/PENDING_APPROVAL|SIGNED|ACTIVE|COMPLETED|TERMINATED` 上可配规则（LNK-07） |
