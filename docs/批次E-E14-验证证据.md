## 0. 改了什么

| 位置 | 改动 |
|---|---|
| `hermes_sync::render_body`（派活 body 模板） | 新增「### 产出文件命名（必须遵守）」：前缀 `<task_no>-<简短描述>.<ext>`，点名禁止 `report.md` / `output.txt` / `result.json`，说明多文件每个都带前缀、云枢会自动补前缀但落盘重名云枢救不了 |
| `hermes_sync::name_output_file`（新增） | `(task_no, name)` → 没带本任务号就补 `<task_no>-`；已带（含 `-`/`_`/`.` 分隔）原样；`0001234` 不会被当成已带 `000123` |
| `task::handler::upload_attachment` | AI 用任务令牌直传时按上面规则改名（人类上传保持原名）；秒传复用别人记录时打 WARN |
| `hermes_sync::relay_done` 兜底路径 | 云枢自己读 workspace 文件上传时同样加前缀（两条上传路径口径一致） |

**二选一选了「自动加前缀」**（不是只打 WARN）：WARN 不改用户看到的文件名，老大反馈的问题依旧；
自动加前缀能让附件列表天然带任务号。代价：同一份字节被第二个任务复用时（内容秒传，`sys_file`
记录共用）仍沿用首次上传的名字 —— 这种情况打 WARN 留痕，不复制记录。

## 1. 派活 body 里有「产出文件命名」那段（真机原文）

派了 2 个任务给 `verify-ai`（`POST /api/business/task/{id}/dispatch-ai` → HTTP 200），
从 Hermes 看板库 `/root/.hermes/kanban/boards/dev/kanban.db` 读回 body：

```
[PASS] dispatch-ai TSK-202610-000328 HTTP=200 hermes=t_f189db50 err=ok
[PASS] body 含「产出文件命名」TSK-202610-000328 assignee=verify-ai status=ready key=cailu-task:01a18ab8-d5b7-70bf-b48b-d6c677eac0a2
    ### 产出文件命名（必须遵守）

    - 文件名前缀用**任务号**：`TSK-202610-000328-<简短描述>.<ext>`
      例：`TSK-202610-000328-selfcheck.md`、`TSK-202610-000328-diff.patch`
    - **禁止**使用无前缀的通用名（`report.md` / `output.txt` / `result.json`）——
      同一个 AI 处理多个任务时会在同一个 workspace 里**互相覆盖**，前面任务的产出会被后一个盖掉
    - 一个任务可以产出多个文件，每个都要带 `TSK-202610-000328-` 前缀
    - 兜底：上传到云枢时若文件名没带任务号，云枢会**自动补** `TSK-202610-000328-` 前缀
      （附件列表里因此不会重名）；但**落盘**的文件仍要你自己按上面的规范命名，
      否则「最后一个任务覆盖前面所有任务的产出」这件事云枢救不了
```

第二个任务（`TSK-202610-000329`，`hermes=t_435d9a17`）同样含该段，前缀换成本任务号。

## 4. 「AI 实际产出文件名」这一项的诚实说明

144 上 Hermes 看板的 dispatcher **没有在跑**（连昨天 T5b 派的两张卡都还停在 `ready`），
所以派活后没有 worker 真的被执行、workspace 里不会长出新文件。本卡对「AI 侧」的验证是：
**用 body 里那张任务令牌、按 body 给的 curl 调用方式自己发了一次上传**（等于 AI 当时该做的动作），
结果如 §2。落盘文件名那一半只能靠 body 里的硬要求（§1），因为那是 AI 侧行为、在云枢管道之外 ——
这一点在验收时需要老大知道，别把「没看到 AI 新产出文件」当成缺陷。
