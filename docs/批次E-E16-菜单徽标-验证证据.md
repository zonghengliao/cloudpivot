## 2. 徽标口径（B 方案，与卡面逐条一致）

| 层级 | 菜单 | 值 | 数据源 |
|------|------|----|--------|
| 目录 | 公告与消息 | 子菜单桶**去重**相加 → 5 | 前端 |
| 菜单 | 公告中心 | 3 | 可见 ∧ 未过期 ∧ 无我的已读回执 |
| 菜单 | 消息中心 | 2 | `sys_notice_receiver.read_flag = false` |
| 菜单 | 公告管理 / 消息通知 | 不显示 | — |
| 目录 | 审批流 | 4 | 前端 |
| 菜单 | 审批中心 | 4 | `biz_flow_task.assignee_id = me ∧ status='PENDING'` |
| 菜单 | 流程定义 / 发起审批 | 不显示 | — |
| 目录 | 工作任务 | **2（不是 6）** | 前端按桶去重 |
| 菜单 | 任务列表 / 看板 / 甘特图 | 2 / 2 / 2 | `owner_id=me ∧ status='TODO' ∧ created_at ≥ now()-7d` |
| 菜单 | 项目 / 帮助中心 | 不显示 | — |

规则的三个落点：

1. **值 0 不渲染**：`v-if="badge > 0"`（不是「显示 0」）；
2. **>99 显示 `99+`**：`t-badge` 的 `:max-count="99"`；
3. **目录不重复累加**：`badgeKeysOfSubtree()` 先把子树里的 **桶名去重** 再求和 ——
   任务三视图共用 `task_todo`，直接相加会显示 6。

## 3. 后端接口

```
GET /api/system/badge/counts   （无权限码，任何登录用户查自己的）
{"code":0,"data":{"announcement_unread":3,"notice_unread":2,"flow_todo":4,"task_todo":2}}
```

- **4 条 count 并发**：`announcement` 的受众（角色 / 部门）要先查一次，其余三条 + 公告计数在 `tokio::join!` 里并发（`Db` 是 `Arc<dyn RawExecutor>` + `&self`，可直接并发）。
- **口径不复制**：公告未读复用 `announcement::model::load_audience + count_unread`、通知未读复用 `notice::model::count_unread`；`flow` 的状态 / 类型取值直接引用 `flow::model::MY_TODO_STATUSES` 与 `flow::dto::TASK_KINDS`（口径只有一份，改列表口径徽标自动跟随）。
- **比卡面多一个 join**：`flow_todo` 额外 `JOIN biz_flow_instance i ON i.deleted_at IS NULL`，否则已软删实例的待办会让「红点数 > 点进去看到的待办数」。
- **失败不降级**：任一查询失败 → 500（返全 0 会让用户以为没有待办）。

## 4. EXPLAIN（灌量后实测，每条 1 行）

灌量：`biz_flow_task` 2005 行 / `biz_flow_instance` 2000 行 / `sys_announcement` 2003 行（`ANALYZE` 后）。

| 桶 | EXPLAIN 关键行 | 结论 |
|----|----------------|------|
| 公告未读 | `Nested Loop Anti Join` → `Index Scan using idx_sys_announcement_list` + `Bitmap Index Scan on idx_sys_announcement_read_user` | 命中 `(user_id, announcement_id)` |
| 通知未读 | `Index Only Scan using idx_sys_notice_receiver_unread`（`Heap Fetches: 0`） | 命中部分索引 |
| 审批待办 | `Index Scan using idx_biz_flow_task_mine` + `Index Scan using biz_flow_instance_pkey` | 命中 `(assignee_id, status, created_at DESC)` |
| 任务待处理 | `Index Scan using idx_biz_task_owner_status_due`，`Index Cond: owner_id + status`，`Filter: created_at >= now()-'7 days'` | 命中 `(owner_id, status, due_date)` 前两列 |

> 说明：卡面写的 `biz_task (owner_id, status, created_at)` 在库里不存在（现网索引是 `idx_biz_task_owner_status_due (owner_id, status, due_date)`）。
> 卡面同时要求「迁移 0」，所以本卡**不新建索引**：`owner_id + status` 走 Index Cond，`created_at` 在索引项上做 Filter（实测 2 行被过滤，耗时 0.017ms）。要变成 Index Only Scan 需另开一张卡加 `(owner_id, status, created_at)` 索引。
