## 4. E4 作废不回滚库存（2 组）—— 代码修复 + 历史数据修复

- **代码根因**：`stockin_handler::cancel_in_tx` 的 `POSTED → CANCELLED` 分支只做了「红冲凭证 + 作废应付」，
  库存/库位账/流水一个都没退（当时那条 `tracing::warn!` 就写着「库存未冲回」）。
- **代码修复（本卡）**：`stockin_model` 新增 `cancel_plan_of` / `reverse_cost` / `reverse_location_qty` /
  `write_cancel_txn`，由 `cancel_in_tx` 在**同一事务**内按「锁库存（material_id 升序）→ 校验可退 →
  退成本账 → 退库位账 → 写 `OUT / PURCHASE_IN_CANCEL` 流水 → 红冲凭证 → 应付作废」执行；
  数量取 `biz_stock_in_item`，**金额取 `biz_inventory_txn` 里该行过账时写入的 `amount`**（不用现价）。
  库存不足 → `409`「该单的货已部分出库（库存 X < 本单 N），不能直接作废；请先做退货入库冲销」。
- **历史数据**（`30_e4_cancel_rollback.up.sql`），实测输出：
  ```
  P9-E4: IN-20261031-000006 第 1 行已退 数量 4.0000 / 金额 24.0000（库存 21.0000 → 17.0000，均价 5.904762 → 5.882353）
  P9-E4: IN-20261031-000007 第 1 行已退 数量 9.0000 / 金额 63.0000（库存 17.0000 → 8.0000，均价 5.882353 → 4.625000）
  ```
  最终 `M-W1A-001/WH01 = 8 件 / 37 元 / 4.625`，恰好等于「剩下的两层加权平均」
  （`IN-000005` 7 件×5 = 35 + 调拨进 1 件×2 = 2 ⇒ 37/8 = 4.625），均价没被污染。

### 4.1 一处与卡面的差异（有理由，必须写清）：`avg_cost` 重算而不是「保持不变」

卡面写「移动加权：减量不改单价」。但作废退的是**这一层入库的原额**（金额取自流水），而当前均价已被
期间内其它入库稀释 ⇒「数量减 q、金额减 a、单价不动」三者必然互相矛盾（`amount ≠ qty × avg_cost`，
直接触发不变式 C4）。
按 `(amount − a) / (qty − q)` 重算在数学上就等于「把这一层从加权平均里摘掉」：
冲销**最近一层**时精确回到冲销前的历史均价，冲销**中间层**时得到剩余各层的加权平均。
单测 `cancel_uses_posted_amount_not_current_avg` 用「100@2 + 100@3 作废第一张」钉住了这个口径
（退 200 不是 250，剩 100 件 / 300 元 / 3.0）。

## 5. G2 PENDING 调拨无审批实例（TK-20261031-000002 / 000004）

- **选择：作废（`PENDING → CANCELLED`）**，不是「退回草稿」。
- **理由**：
  1. `PENDING → CANCELLED` 是 `transfer_model::LEGAL_EDGES` 里**已有**的合法边，数据与状态机自洽；
     `PENDING → DRAFT` 不在合法边里，落地要改 `transfer_*.rs`（本卡硬红线 6 禁止碰，P7/P8 在用），
     用 SQL 直接写一个状态机不认的状态等于给下一张卡埋雷；
  2. 语义也对得上：这两张单**从来没有审批实例**，谁也无法批准它 —— 它不是「用户想撤回的草稿」，
     而是一张提交失败的单 ⇒ 作废重开（P5 已保证新单提交即生成实例）；
  3. 作废不动库存：`PENDING` 从未结算（没写过 `biz_inventory`）。
- **动作**：`40_g2_transfer_stuck.up.sql`（带 `cancel_reason` 说明 + `cancelled_at`）。影响 2 行。
- **遗留**：若产品确实要「撤回重新提交」，需要另派卡在 transfer 状态机加边并补接口。
