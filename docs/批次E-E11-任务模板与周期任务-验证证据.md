## 4. 周期任务（**真调度器**，不是手调函数）

调度注册（prod 启动日志）：

```
{"message":"周期任务生成任务已注册（E11）","invoke_target":"business_task_recurring","cron":"0 */5 * * * *"}
{"message":"定时任务 business_task_recurring [0 */5 * * * *] 已排程","target":"alun_plugin::scheduler"}
```

两轮生成（每轮把 `next_run_at` 拨到 1 分钟前，等调度器**自己的 5 分钟刻度**）：

```
[04:25:02Z] 模板已建（enabled=true，cron=0 9 * * *）：next_run_at=2026-10-31T01:00:00Z   ← cron 算出的次日 09:00 CST
[04:30:04Z] PASS 第一轮生成：TSK-202610-000014|2026-10-30 12:30:00（等待 301s）
[04:30:04Z] 模板排期：last_run_at=2026-10-30 12:30:00 | next_run_at=2026-10-31 09:00:00   ← 自动推进到下一次 cron
[04:35:01Z] PASS 第二轮生成：TSK-202610-000016|2026-10-30 12:35:00（等待 297s）
```

生成记录（验收库）：

```
TSK-202610-000014|E11-周期任务-每天九点|RECURRING|12:30:00|parent=-
TSK-202610-000015|周期子任务 A        |RECURRING|12:30:00|parent=01a18b12-…   ← 模板子任务一并落库
```

停用后不再生成：`PUT /business/task/template/{id}` 置 `enabled=false` → 返回 `enabled=False, next_run_at=None`；

## 9. 已知口径差异（如实记录）

1. 卡面写 `GET /task/burntdown`（多一个 `t`），实现按**正确拼写** `burndown` 注册，与模块名
   `task/burndown.rs` 一致；前端与验收脚本都用 `/api/business/task/burndown`。
2. 卡面说「按 `completed_at` 反推」，本库没有该列，等价列是 `biz_task.done_at`（T2 状态机写入 / 重开清空）。
3. 模板表比卡面多了 `owner_id` / `project_id` 两列：`biz_task.owner_id` 是 `NOT NULL REFERENCES sys_user(id)`，
   没有它「一键建任务」生成不出合法任务行；空值兜底顺序 = 请求体 → 模板 owner → 模板创建人 → 操作人。
4. `board` 参数口径：`all`（缺省，数据范围 ∪ 我参与）/ `my`（只算我参与）。卡面只写了
   `?project_id=|board=`，没有定义 board 的取值域，这里按列表页「只看我的任务」同义实现并写进接口文档。
