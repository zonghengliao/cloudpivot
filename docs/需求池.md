## RP-2026-001 · 序列号「先打码后收货」（`GENERATED` 态 + 入库单引用已生成号段）

| 字段 | 内容 |
|---|---|
| **优先级** | **P2**（已确认方向，等触发条件，不排期） |
| **状态** | 待触发 |
| **来源** | `docs/adr-20261031-erp-serial-batch-generate-semantics.md` §2 候选② / §3 第 6 条；`docs/datafix-20261031-p11-m-w1a-004-recur.md` §6 遗留 ② |
| **提出日期** | 2026-10-31 |
| **提出人** | 总管 manong（拍板口径）／产品经理整理入库 |

### 1. 触发条件（满足才立项）

**客户/业务方明确要求「先打码后收货」**，即：需要先在系统里生成号段、打印标签贴到实物上，货到之后再凭收货单把号段正式入库；且现有口径
（「批量生成 = 无来源入库，必须录成本」，ADR 主口径 ①′）在账务上无法满足其要求
（典型信号：客户不接受"号一生成就进库存/进成本"，或验收时反复问"为什么还没收货就有库存"）。

只要没有这条明确诉求，**不做**——ADR ①′ 已经把当前业务闭环补齐（录成本 + 写两本账），够用。

### 2. 现状与问题

| 事实 | 位置 |
|---|---|
| 序列号只有三态：`IN_STOCK` / `OUTBOUND` / `SCRAPPED`，没有"已生成但未入库" | `backend/src/business/erp/serial_model.rs:117-124` |
| `batch_generate()` 一次调用做三件事：取号 → 落库（状态写死 `IN_STOCK`、`inbound_at = now()`）→ `link_inventory()` 重算库存并记流水 | `serial_model.rs:750` / `:781` / `:715` |
| `recompute_quantity()` 把 `biz_inventory.qty` 算成「该 物料×仓库 下 `status='IN_STOCK'` 的件数」 | `serial_model.rs:592` |
| 收货入库 `stockin_model` 是唯一正确写两本账的入口（`apply_cost` + `apply_location_qty`），且**故意不调用** `batch_generate` | `stockin_model.rs:1059` / `:1176` / `:51-70` |

⇒ 问题的本质：**「取号」和「入库」是同一个动作**，取号即占库存、即进成本。

### 3. 目标语义

| 动作 | 现在的效果 | 本需求的目标 |
|---|---|---|
| 批量生成号段 | 落 `IN_STOCK`，`qty += N`，进成本 | 落 **`GENERATED`**：号存在、可打印、可查询，但 **`qty` 不变、金额为 0、不写库位账** |
| 收货 / 入库 | （无此能力） | 入库单**引用已生成号段** → 号段批量转 `IN_STOCK`，两本账按 `apply_cost` / `apply_location_qty` 正常写 |
| 作废未使用的号 | （无此能力） | `GENERATED → SCRAPPED`（或专用「号段作废」），不动库存 |

**账务口径直接复用 ADR 第 3 条**：入库那一刻走移动加权，`new_avg = round((old_amount + N×cost)/(old_qty + N), 6)`；
生成阶段**不产生任何金额**，因此也不会触发"零成本库存"这一类判据（生成的不是库存）。

### 4. 影响面（改动清单）

| # | 位置 | 改动 |
|:---:|---|---|
| 1 | `serial_model` 状态机 | **三态扩四态**：新增 `GENERATED`；补合法迁移边（`GENERATED→IN_STOCK`、`GENERATED→SCRAPPED`，禁止 `GENERATED→OUTBOUND`）；`recompute_quantity()` 保持只数 `IN_STOCK`（需补断言 `GENERATED` 不计入） |
| 2 | 入库单（收货）改造 | `stockin_model` 新增能力：**引用已生成号段**（按号段/批次选择 `GENERATED` 号 → 过账时绑定到入库行并转 `IN_STOCK`，回填 `source_type/source_id`）；数量必须等于引用号件数 |
| 3 | 前端两套列表 | ①**号段池**（`GENERATED`，未入库，可打印/作废）②**在库序列号**（`IN_STOCK` 起）；序列号页需拆视图或加状态筛选，批量生成弹窗语义改为「生成号段」 |
| 4 | 权限点 | 新增「号段生成」「号段作废」，与 `business:erp:serial:generate` 拆开（生成≠入库） |
| 5 | 报表 / 接口口径 | 库存件数 = `IN_STOCK` 计数不变；新增"待入库号段"指标；`GET /serial/page` 默认筛选需明确是否含 `GENERATED` |
| 6 | 数据迁移 | 存量 `IN_STOCK` 不动、不回填；已在用的号段无需迁移（预期 0 迁移，若有枚举落库再单开） |
| 7 | 文档 | `docs/对客验收手册.md` §3.2① / §3.3 必须同步改：届时「生成」不再等于「入库」，走查后清理口径随之变化 |

### 5. 不做的后果

客户若确实"先打码后收货"，只能继续用「批量生成」硬造在库 + 事后调账（红冲 / 盘点），账实不符的风险留在客户侧。

### 6. 验收要点（立项后按此验收）

1. 生成 100 个号（物料须一物一码）⇒ 号段池 100 条 `GENERATED`，`biz_inventory.qty = 0`、`amount = 0`、库位账合计 = 0；
2. 收货单引用其中 60 个过账 ⇒ `qty = 60`、`amount = 60 × unit_cost`、`avg_cost = unit_cost`、库位账合计 = 60，`erp_invariants.py` **32/32 / BLOCKER 0 / WARN 0**；
3. 未引用的 40 个仍留在号段池，可作废（`SCRAPPED`）且不影响库存与金额；
4. 引用数量 ≠ 入库数量时拒绝过账（400，明确文案）；
5. 二次收货（不同单价）⇒ 移动加权正确滚动；
6. 既有 W2b/W2c 链路（收货、出库、报废、调拨）单测全绿。

### 7. 依赖与预估

- **依赖**：ADR 第 3 条的账务实现（`apply_cost` / `apply_location_qty` 复用）——与「必须录成本」那一半可解耦，本需求只依赖"入库正确写两本账"这部分。
- **粗估**（需架构师复核）：后端 2 人日 ／ 前端 2 人日 ／ 测试 1 人日。
- **风险**：这是**语义增强**不是 bug 修复；会打断客户当前"点完批量生成就看到库存"的演示路径（ADR §2 已评估），所以必须等触发条件，不能提前做。

## 如何新增条目

1. 先判断：是 **P0/P1**（现在就要做）→ 直接立 kanban 卡，不进本池；
2. P2/P3 才进池，且**必须写清触发条件**（"客户提出 X" / "并发超过 Y" 这类可观察的信号）；
3. 编号规则：`RP-<年>-<三位序号>`，不复用、不回收；
4. 触发后：从本池移出 → 立项 → 在概览表把状态改为「已立项（卡号）」。
