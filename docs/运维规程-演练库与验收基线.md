## 3. 干净库怎么建（可复现）

```bash
# 在 145、仓库根目录。145 的库属主/账号都是 cloudpivot（脚本默认 alun，必须显式传）
ERP_DB=cloudpivot_dev_clean RECREATE=1 PORT=18049 \
  OWNER=cloudpivot DB_USER=cloudpivot DB_PASS="$NIK_DATABASE_PASSWORD" \
  bash scripts/verify/erp_clean_db.sh
```

要点：

- `RECREATE=1` 会 `dropdb --force` 再 `createdb -O cloudpivot`，只有本卡自己的库能这么干；
- 用**同一个二进制**起一次实例，让引擎把 `migrations/` 全部应用 + 完成 bootstrap（种子菜单/角色/流程/根部门 HQ、admin 落位 HQ）；
- 记下指纹：`schema_migrations` 287 条 versioned（max `367`，含种子共 298 行）、菜单 433、admin 1 人；
- 全新库跑完不变量必须 **80/80**（`H6` 的种子 `is_system` 由迁移 V0366 补，早于 V0366 的库会红）。

## 4. 验收闸（**这是硬前置条件**）

```bash
bash scripts/ops/acceptance_gate.sh            # 默认 DB=cloudpivot_dev_clean
DB=cloudpivot_x bash scripts/ops/acceptance_gate.sh   # 换库；生产库名会被拒绝（exit 2）
```

三条判据全过才退出 0：

1. `scripts/verify/erp_invariants.py` 全量 **80/80**（BLOCKER 0 / WARN 0）；
2. 孤儿应收 **0**（`source_type='SALES_OUT'` 且 `source_id` 指向的出库单不存在）；
3. 库存 vs 流水差异 **0 组** + 逐桶（物料×仓库×库位）成本账 vs 库位账差异 **0 组**。

**规定：**

- **每次演练开始前、每次上线前，必须先跑验收闸并拿到「✅ 全绿」**（退出码 0）。退出码非 0 不许开始演练、不许提交上线。
- 验收证据只能来自 `cloudpivot_dev_clean`（或刚恢复演练重建的库）；**`cloudpivot_dev` 的巡检结果永远不算证据**。
- 闸本身要能红：对 `cloudpivot_dev` 跑应得 `验收闸：❌ 未通过`（RC=1）—— 实测见证据 `51_acceptance_gate_dev.out`。

## 6. 常见坑（血泪）

| 现象 | 原因 / 正确做法 |
|---|---|
| 「库存 vs 流水 11 组差异」 | 汇总 SQL 用 `biz_inventory LEFT JOIN biz_inventory_txn` 再 `SUM(i.qty)`：`biz_inventory` 是 per-bucket 桶表，流水被每个桶行重复计入 ⇒ **假差异**。必须两侧先聚合再 `FULL JOIN`（`acceptance_gate.sh` 已按正确口径实现） |
| 「孤儿应收 5 张」跑出 21 行 | `MANUAL` 应收的 `source_id` 是挂账时生成的占位 UUID，本来就没有出库单。判据必须加 `source_type='SALES_OUT'` |
| 清场后 `B2 库存金额 = 1405 余额` 红 10 元 | 序列号出库写了 `SERIAL_OUT` 凭证（`source_id` = 序列号 id），只清 `SERIAL_BATCH` 会漏。`02_smoke_fixture_cleanup.sql` 里有无主 SERIAL_* 凭证兜底 |
| 隔离实例 `/health` 200 但登录报口令错 | 端口被别人的实例占着：新进程 bind 失败。必须 `ss -ltnp` 核对 listener pid == 自己起的 pid（`00_start_instance.sh` 已断言） |
| 起实例打印「数据库未初始化」后 panic | CWD 必须是 `backend/`（迁移目录按 CWD 解析） |
