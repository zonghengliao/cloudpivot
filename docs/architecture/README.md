# 架构与设计文档

本目录存放**设计与决策记录**，以及可交互的架构视图。

## 功能关系图（可直接打开）

[`cloudpivot-func-graph.html`](cloudpivot-func-graph.html) —— 双击用浏览器打开，**零外部依赖**（脚本/样式/数据全部内联），离线可用。

| 项 | 说明 |
|---|---|
| 节点 | **87 个功能页**，全部从 `sys_menu` 表导出，与系统里看到的菜单一一对应 |
| 连线 | **66 条流转**，单据之间的业务流向（采购→入库→应付→凭证 等） |
| 分组 | **11 个业务域**，按颜色区分 |
| 交互 | 拖动节点 / 滚轮缩放 / 空白拖动平移 / 点节点高亮上下游 / 双击重置 |

**图能直接回答的问题**：

- 一张单据从发起到入账走过哪些环节
- 哪些功能被引用了但自己不发起流转（26 个配置类功能）
- 审批流是怎么横向贯穿 6 个业务域的（全部汇到同一个「发起审批」）

**数据口径**：

```
节点来源   sys_menu WHERE path IS NOT NULL AND name NOT LIKE '%:%'
           排除权限码（business:xxx:yyy），只保留真实功能页
连线来源   单据间业务流转关系（按各模块数据模型手工核对）
更新时机   菜单结构变化后需要重新生成
```

**重新生成**（仓库内脚本）：

```bash
# 1. 从数据库导出菜单
psql "$DB" -tA -F'|' -c "..."   # 见 gen_nodes.py 注释

# 2. 生成 HTML
python3 scripts/gen-func-graph.py
```

## 约定

1. **决策必须写「为什么」和「否决了什么」** —— 只写结论的文档等于没写。
2. **设计文档与代码同仓** —— 改代码的提交应同时更新对应设计。
3. **图是生成的，不是手画的** —— `cloudpivot-func-graph.html` 由脚本从数据库生成，菜单变了要重新生成，不要手改。
