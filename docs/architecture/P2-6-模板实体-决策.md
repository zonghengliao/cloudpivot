## 0. 一句话结论

**「模板」在本系统里不是实体，是流程定义的一个角色（预置标记 `is_system`）。**
产品层面**承认这一点并按 A 收口**：删掉「模板库」这个独立功能项与菜单节点，术语统一为**「标准流程」**，把卡片墙降级为流程定义页的一个视图；**不新建 `biz_flow_template` 表**。
同时修掉 3 处让「像是有两个东西」的具体缺陷（下面 §1.2 的 H5 / H9 / D6），其中 2 条错标数据是迁移漏填字段造成的，属**真实数据缺陷**，与概念选择无关，无论选 A 还是 B 都得修。

## 2. 决策：A —— 合并概念（+ 术语收紧），否决 B（建独立模板表）

### 2.1 术语契约（决策后唯一的说法）

「模板」一词在 UI / 文档 / 新代码里**下线**，改称「标准流程」。实体只有一个：

| 层 | 名字 | 判据 | 谁能改 |
|---|---|---|---|
| 实体（唯一） | **流程定义** `biz_flow_def`（+ 版本 `biz_flow_def_version`） | — | 有 `business:flow:update` 的人 |
| 角色 | **标准流程** | `is_system = TRUE`（系统迁移预置） | 不能改图，只能**另存为**副本 |
| 角色 | **我的流程** | `is_system = FALSE`（自建 / 另存为出来的副本） | 全权 |
| 角色 | **已发布 / 草稿 / 停用** | `biz_flow_def.status` | — |
| 视图 | 标准流程卡片墙 | `is_system = TRUE AND status='PUBLISHED'` 的展示投影 | 只读 + 「看流程图 / 另存为 / 启用停用」 |

一句话口径：**「标准流程」= 打了预置标记的流程定义；「另存为」= 用它复制出我的流程。没有第三个东西。**

### 2.2 为什么不建表（B）

| # | 理由 | 依据 |
|---|---|---|
| B-1 | **B 会造出「谁是真源」的死结**：模板版本 + 流程版本两级版本，客户改完 def 后要不要回写模板、标准模板升级要不要推到客户已经在跑的 def —— 这些都是产品级难题，而现在**没有一条真实需求**逼我们解它（11 条定义、0 个实例在 `cloudpivot_manual`；客户副本 `_custom` 一个都还没产生，probe `P3a`=0） | probe `D5`=0、`P3a`=0 |
| B-2 | **B 的成本压在「迁移 11 行 + 12 版本」上**：模板表要有 `_version` + `_node` + `_edge`，等价于把 `biz_flow_def*` 三张表复制一遍；而 `duplicate()` 已经实现了「复制定义（节点+连线+审批人+元信息）→ 新 DRAFT」的完整语义（`handler.rs:3054-3157`），**B 能做的事现在已经在做** | `handler.rs:3029-3157` |
| B-3 | **B 治不了真正的病**：用户困惑的直接来源是 ①模板库混进非标准流程（H5）②名字与标记矛盾（H9）③两个菜单一个表（D6）。建表后如果 UI 口径不变，这 3 条**一条都不会消失**，只是多了一张要同步的表 | §1.2 |
| B-4 | **B 会和 ARCH-5 打架**：ARCH-5 已把「模板墙」定位成**发起中心**的视图（§12.4「模板墙 + 表单渲染」，卡片数据直取 `biz_flow_def_version.node_count`），并规划 `business:flow:template:read` 权限（§13.2）。若此刻建独立模板表，ARCH-5 的发起中心要改成读模板表 → 与「实例绑定 def 版本」（`instance.def_id` + `graph_snapshot`）冲突 | `docs/architecture/ARCH-5-工作流引擎设计.md:3508-3560, 3662` |

**被否的 B 方案里最强的论点**（诚实记录）：*「标准模板应能独立演进并批量推送到客户已在用的流程，而 def 是客户资产不能动」* —— 这条成立，但**它今天不成立**：客户流程一旦发起就把图冻进 `instance.graph_snapshot`，改 def 不影响在跑的实例（这正是现有设计的口径，见 `duplicate()` 注释「不复制实例、历史审批记录仍挂原 def_id」）。所以「模板升级」的真实需求是**分发**，不是**建模**，用「预置流程版本号 + 巡检提醒」更便宜。

### 2.3 什么时候翻案改成 B（量化触发判据，写清楚免得反复吵）

出现**任意两条**才考虑建表：

1. 出现「同一标准模板按客户/租户参数化生成多份 def」的需求（≥ 3 家租户同一 skeleton 不同阈值）；
2. 出现「标准模板升级需批量下发到 N 个客户 def」的需求，且 N ≥ 5；
3. 客户自建 def 数 ≥ 50 且其中 ≥ 30% 由同一标准流程复制而来（那时才谈得上「模板族谱」）；
4. 需要「模板级审批」（改模板本身要走审批）—— 现在没有，且用 def 版本 + 发布校验已覆盖。

翻案前先量：`select count(*) from biz_flow_def where not is_system`、`select count(*) from biz_flow_def where flow_code like '%\_custom'`。
