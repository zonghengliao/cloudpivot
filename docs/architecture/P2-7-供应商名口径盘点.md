## 1. 先分清「三套名字」

```
        ┌──────────────── biz_supplier（主数据，唯一真相）─────────────────┐
        │  id(uuid)  ← 全系统唯一的关联键                                  │
        │  supplier_name  VARCHAR(200) NOT NULL   ← 全名（唯一显示名）      │
        │  short_name     VARCHAR(100) NULL       ← 简称（**只用于检索/导入**）│
        └──────────────────────────────────────────────────────────────────┘
                    │ 冻结（建单时抄一份）
                    ├──────────────► biz_purchase_order.supplier_name_snapshot   （V0198）
                    ├──────────────► biz_contract.party_b_name                   （V0195，签约名）
                    ├──────────────► biz_fixed_asset.supplier_name                （V0229，建卡名）
                    └──────────────► biz_flow_instance.form_data.supplier_name    （提交审批时冻结）
```

三个必须分清的概念（沿用《快照一致性巡检与告警设计》1.1 节的判据）：

| 概念 | 含义 | 能不能改 |
|---|---|---|
| **关联（link）** | 用 `id` 指向主档，回答「**是哪一家**」 | 不适用（id 不变） |
| **快照（snapshot）** | 单据创建/提交那一刻抄下的名字，回答「**当时叫什么**」 | **不能改**（审计证据） |
| **现值（current）** | 按 `id` 关联主档**现在**的名字，回答「**现在叫什么**」 | 主档改名即变 |

> 判据一句话（《快照一致性巡检与告警设计》1.1 节）：**能重算的偏移是 bug，不能重算的偏移是历史。**
> 「快照名 ≠ 现名」是历史，不修；「建单晚于改名却写了旧名」是 bug，要报。

## 3. 使用口径（本项目从此按这 6 条判）

> 与卡面「显示用快照（历史单据）+ 关联（详情页显示"现在"）」的**取舍说明**见 §3.1。

| 编号 | 规则 | 为什么（一句话） |
|---|---|---|
| **S1** | **关联、过滤、汇总、JOIN 一律用 `id`；禁止用名字 JOIN / WHERE / GROUP BY** | 名字会变、会重名；`id` 才是主键。按名字 join 一次改名就静默少行 |
| **S2** | **列表 / 报表 / 导出 = 现值**（按 `id` 关联主档）；主档已删或查不到时**回落到单据快照名**，不得落到 uuid | 列表是操作入口：用户找的是「这家现在叫什么」；报表按 `id` 汇总、名字只做标签，才能让同一家的历史单据归到一行 |
| **S3** | **快照只出现在两处**：① 冻结文书（合同签约名、资产卡、审批单、凭证/科目录入）；② 详情页与现值**并列展示**（范式：合同详情的「乙方」+「签约时乙方快照」） | 「当时是谁」是审计问题，必须能回答；但答案要和「现在是谁」摆在同一个屏上，不能只给一个 |
| **S4** | **快照永不修改**（含"顺手把历史单据改名"的修数）；快照与现名的偏差**只报不修**（AP-8） | 改历史快照 = 销毁审计证据 |
| **S5** | **简称只用于检索与导入**：不得出现在单据、报表、导出、打印里；也不得代替全名参与任何比较 | 简称是"人嘴里的叫法"，不是主体标识；混用会让「同一家有两个名字」变成真的 |
| **S6** | 新增单据表**不必**都加名字列：只在「名字是审计证据」时才落快照（合同/资产/审批），其余用 `id` 关联 | 卡面明确不加；名字列越多，漂移面越大 |

### 3.1 为什么 S2 把「列表」定成现值，而不是卡面写的「列表用快照」

卡面的原句是「显示用快照（历史单据）+ 关联（详情页显示"现在"）」。按本仓实测，**反向安排更稳**，理由三条：

1. **报表按名字汇总的现实需求**：同一家供应商改名后，若列表/报表显示快照，一次改名就会在汇总里**多出一行**（正是本卡要防的"按名字汇总对不上"）。按 `id` 汇总 + 现值做标签，历史单据全部归到同一家。
2. **代码现状 5:2**：合同列表 `contract-logic.ts:231`、应付 `payable_query.rs:87`、收货 `stockin_handler_query.rs:48`、提醒 `reminder_*.rs`、导出 `erp_doc.rs:396` 全是现值；只有采购单后端 DTO 下发快照（且前端又覆盖成现值）。统一成现值改动面最小、且不留"同一处两套来源"。
3. **审计要求仍然满足**：S3 要求详情页把快照**并列**展示（合同详情已是这个形态），并且快照永久留库、DI-26 每天盯偏差 —— "当时是谁"从未丢失。

> 这条取舍是本卡的**决策**，不是遗漏；若产品要改成"列表显示快照"，只需改 S2 一处并同步 §4 的偏离项，S3/S4/S6 不受影响。

## 5. 巡检 DI-26：供应商 ID → 名字映射唯一性

### 5.1 它查什么（6 类，一条视图）

`di.c_di26`（`docs/architecture/snapshot-drift/10_checks.sql`）输出统一的 11 列，`drift_kind` 只有 `DEFECT` / `SNAPSHOT` 两种，`severity` 只有 `WARN` / `INFO`：

| 分支 | 判据 | 级别 | 为什么是这个级别（照 §2.3 的边界） |
|---|---|---|---|
| **NAME_DUP** | 两个**活跃**供应商 `lower(btrim(supplier_name))` 相同 | **WARN** | 下拉框里两个选项长得一样、按名字汇总必然合并 ⇒ 选错主体的人为风险；但 `id` 关联没错、钱没动、链没断 ⇒ 不是 BLOCKER |
| **SHORT_DUP** | 两个活跃供应商 `lower(btrim(short_name))` 相同（非空） | **WARN** | 简称只服务检索（`model_master.rs:816`），重复会让"搜 A 出 B" |
| **SHORT_SHADOWS_NAME** | 某家的简称 == **别家**的全名（归一后） | **WARN** | 三套名字互相污染的最短路径：单据上出现这个名字，人分不清是全名还是简称 |
| **SNAPSHOT_DRIFT** | 快照名 ≠ 主档现名：采购单 / 合同 / 资产卡 / 审批单（4 个来源合成一支，`entity_type` 区分） | **INFO** | 合法历史（1.1 节的「不能重算的偏移」）：改名后历史单据**必须**保持旧名。只留痕不进告警队列；它同时是"按名字汇总会对不上"的实测口径 |
| **SNAPSHOT_MISSING** | 采购单有 `supplier_id` 但快照为 NULL（V0198 不回填存量） | **INFO** | 历史事实；这类行显示只能回落现值 ⇒ 名字会"跟着改名变"。仅在 `supplier_name_snapshot` 列存在时判（`di.di_capability.has_po_contract_id`） |
| **SNAPSHOT_LATE_WRITE** | **SPOT** 采购单 `created_at > 主档 updated_at` 却仍是旧名 | **WARN** | **可重算的偏移 = bug**：建单时主档已是新名，快照却写旧名 ⇒ `purchase_handler::resolve_head` 漏取现值。合同采购**不在**此类（它的快照按设计来自合同签约名，由 DI-01 盯 PO↔合同） |

设计要点（写在这里免得下一个人重踩）：

1. **不重复计数**：`SNAPSHOT_LATE_WRITE` 的行**从** `SNAPSHOT_DRIFT` 里排除（否则同一行同时算 WARN+INFO，汇总数虚高）。
2. **不报"还没这列"**：`SNAPSHOT_MISSING` 只在快照列存在时才判（否则 V0198 之前的库会把所有采购单报成"缺快照"）。
3. **资产分支走兼容层**：`biz_fixed_asset` 是 V0229 才有的表，DI-26 不直接引用它，而是引用 `di.v_asset`（`00_install_compat.sql` ⑤：表不在时给零行空壳）。**实测两条阶段都装得上**（见 §5.4）。
4. **归一规则**：`lower(btrim(x))` —— 首尾空格/大小写不同算同名（这类"看起来一样"的脏数据正是合并风险源）；**不做**内部空格折叠（会把 "A B" 与 "AB" 这种真实不同名判成同名）。
