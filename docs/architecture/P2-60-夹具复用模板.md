> 卡：`t_b0709864`　基线：`83609654`（P2-59 = C1 内核抽 crate 之后）　2026-11-15

## 1. 一句话

把「手写的零寿命连接池（144 处）+ 每次重新建库」换成**一套模板**：

| 层 | 改前 | 改后 |
|---|---|---|
| 连接池 | 每处 `ensure_db()` 手写 `max_lifetime = idle_timeout = ZERO` ⇒ **每条语句新建一条连接** | `cloudpivot_kernel::shared::test_fixture::connect(&url)`：池建在**进程级后台 runtime** 上，连接真正复用 |
| 库 | 每次跑测试重新「建空库 + 336 个迁移 + 种演示组织」 | 模板库建**一次**，`CREATE DATABASE … TEMPLATE` **142 ms** 克隆一份，多套测试共用 |

全量 lib 套件实测：**2 532 s 只跑到 5 135/5 448 条就被杀**（旧基线日志）→ **162 s 跑完 5 448 条**。

## 2. 根因：为什么过去只能「每条语句新建连接」

- `#[tokio::test]` 默认 `current_thread`：**每个用例一个 runtime，用例结束即销毁**；
- `DB`（`nik_web::resources::set_db`）是**进程级** `OnceLock`：整个 lib 套件共用一个池；
- tokio-postgres（以及 nik 的 PG 驱动）在建连时把**驱动任务 spawn 到当前 runtime** ——
  用例一结束，池里的连接就再没人 poll，下一个用例借到的是**死连接**（`connection closed`）。

历史逃逸手法（全仓 144 处，逐字同构）：

```rust
let mut config = DatabaseConfig::from_url(&url);
config.pool.max_lifetime = Some(std::time::Duration::ZERO);   // is_available() 恒假
config.pool.idle_timeout = Some(std::time::Duration::ZERO);
match Db::connect_with(&url, config).await { … }
```

`max_lifetime = 0` ⇒ `pop_available()` 永远弹不到可用连接 ⇒ **每条 SQL 都走一次完整握手**
（TCP + 认证）。99 → 145 的 PG 单次握手 1~3 ms，5 448 条用例的每条语句都付一次：
这就是 42 分钟跑不完的全部原因。

### 直接取证（同一个进程、同一个库）

一次性探针（不入库，跑完即删）用历史写法走两遍：

```
OLDWAY: runtime#1 pid=1294707
OLDWAY: runtime#2 pid=1294708, 再取=1294709   ← 每条语句一条新连接
```

模板写法（`shared::test_fixture` 自带的 `t01` 用例，**已入库**）：

```
test shared::test_fixture::tests::t01_pool_survives_runtime_swap_and_reuses_connections ... ok
```

它钉三条断言：① runtime#1 里建池并查 → pid；② **runtime#1 被 drop 之后**新 runtime 用同一个池查 →
**同一个 pid**（连接活着）；③ 同一 runtime 连查两次 → **pid 相同**（连接被复用，不是每次新建）。


"在一个常驻的专用 thread + runtime 里建连"）—— 本卡把它收敛成一处模板，供全仓共用。

## 5. 库侧：建一次库，多套测试共用

  产出模板库 `cloudpivot_test_full`（实测 178 表 / `admin` + 6 个关键角色成员 / 业务单据 0 行）。
- **每次**：`CREATE DATABASE … TEMPLATE cloudpivot_test_full` —— **142 ms**（178 表，0 次迁移、0 次种子）。
- 新增 `scripts/verify/fixture_template_suite.sh`：**克隆一次 → 同一份库上依次跑 N 套**（默认
  `business::erp::voucher` / `business::hr` / `system::`），逐套打点耗时与条数，红套自动保留现场；
  `PGHOST` 缺省按「本机 PG 活没活」自动选（145 走 loopback，99 走 172.18.10.145），与卡面数据库约束一致。


## 9. 复用与自检

- **用**：新模块的 `ensure_db()` 直接 `match cloudpivot_kernel::shared::test_fixture::connect(&url).await`，
  不要再手写池参数；需要额外池参数用 `pool_config` + `connect_with`。
- **别退回**：任何 `max_lifetime = Some(ZERO)` / `idle_timeout = Some(ZERO)` 都等价于「每条语句一条新连接」。
  `shared::test_fixture::tests::t01` 会钉死这条（pid 复用断言），CI 里跑 `--lib` 就能拦住。
- **模板库指纹随树走**：模板库是「被测树自己的二进制」跑出来的（迁移编译期内嵌），
  换树（P2-C 后续批量抽包）后要重建模板库，否则表数与迁移版本对不上。
