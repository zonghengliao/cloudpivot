# 云枢附件能力与 PDF 导出 · 补全规划

> 版本 v1.0 · 2026-11-07
> 状态：**规划中（等 P0 演练 / P2 采购补齐 / P3 工作流引擎 跑完后再派卡）**
> 来源：用户实测反馈 —— 「很多地方应该要做附件上传的，但没有上传的步骤和上传的地方」

---

## 一、现状盘点（实测）

### 1.1 已有能力（后端通用，不用改）

| 项 | 现状 |
|---|---|
| 附件表 | `biz_doc_attachment(doc_type, doc_id, file_id, file_role, remark, uploaded_by)` |
| 文件表 | `sys_file`（含秒传：内容 hash 命中复用同一条记录） |
| 上传接口 | `POST /attachment/upload`（multipart：doc_type / doc_id / file_role / remark / file） |
| 查询接口 | `GET /attachment/list?doc_type=&doc_id=` |
| 类型枚举 | `DocKind` **103 项**，每一项自带 `exists_sql()` 做单据存在性校验 |
| 配额 | `count_by_doc` 限制单单据附件数 |
| 角色分类 | `file_role` 字段（如 `CONTRACT_SCAN` 合同扫描件） |
| 前端组件 | `DocAttachmentPanel.vue`（通用附件面板，已封装） |

**结论：后端能力完整，缺的全在前端和业务规则层。**

### 1.2 前端接入现状（43 个模块，只有 5 个接了）

```
✅ contract    合同        详情区
✅ purchase    采购订单    详情区
✅ payable     应付        详情区
✅ stockin     入库        详情区
✅ expense     报销        详情抽屉

❌ 其余 38 个模块完全没有附件区
```

### 1.3 缺口分类

| 缺口 | 性质 | 影响 |
|---|---|---|
| **G1 附件无法在线预览** | 能力缺失 | 扫描件/发票影像要下载才能看，效率低 |
| **G2 部分单据「必须」有附件才能提交** | 业务规则缺失 | 无票报销、无回单收款，财务无法审计 |
| **G3 38 个模块无附件区** | 覆盖缺失 | 想传没地方传 |
| **G4 单据/审批/工单无法导出 PDF** | 能力缺失 | 无法打印、无法归档、无法发给外部（供应商/客户） |

## 二、业务判断：哪些单据「新建必传附件」

> 判定口径：**没有这份附件，这笔业务在财务/税务/法务上就不成立**（否则只是"建议补"）。

### 2.1 🔴 必须传（不传不能提交审批）

| 单据 | 必传附件 | 依据 |
|---|---|---|
| **发票 invoice** | 发票影像（PDF/图片） | 税务要求留存发票原件影像 |
| **收款单 receipt** | 银行回单 | 对账唯一凭据，无回单无法核销 |
| **付款单 payment** | 银行回单 / 付款凭据 | 同上 |
| **费用报销 expense** | 票据（发票/收据）**≥1 张** | 无票不能报销，审计红线 |
| **固定资产 asset（新增时）** | 购置发票 + 验收单 | 入账凭据，固定资产台账依据 |
| **采购退货 purchase-return** | 退货单签字件 / 供应商确认 | 货物已出，必须有凭据 |
| **销售退货 sales-return** | 客户确认单 / 退货原因照片 | 防虚假退货冲减收入 |

### 2.2 🟡 建议传（可保存，提交时提示「缺附件」但不阻断）

| 单据 | 建议附件 | 说明 |
|---|---|---|
| 合同 contract | 合同扫描件（`CONTRACT_SCAN`）+ 补充协议 | 法务要求，但允许后补（正在签署中） |
| 采购订单 purchase | 供应商报价单 / 客户 PO | 采购依据 |
| 盘点单 stock-take | 盘点表签字扫描件 | **盘点确认时**必有，建单时可无 |
| 期初余额 opening | 上年审计报告 / 期初依据 | 上线一次性 |
| 调拨单 transfer | 调拨审批单 | 内部管控 |
| 供应商 supplier | 营业执照、开户许可、资质证书 | 准入资料 |
| 客户 customer | 营业执照、信用资料 | 授信依据 |

### 2.3 🟢 可选（不强制，按需）

```
销售订单 sales-order（客户 PO 可传可不传）
发货单 shipment（签收单可后补）
出库单 stock-out（领料单）
预算 budget / 折旧 depreciation / 期间 period / 年结 year-end
报表 report / 单号 seq / 币种 currency / 汇率 exchange-rate
单位 unit / 库位 location / 物料 material（图片另说，走 sys_file 即可）
```

### 2.4 特殊规则

```
① 发票、收款、付款、报销 → 提交审批时硬校验，缺附件直接拒绝（后端也校验）
② 合同 → 提交时软提示「建议上传扫描件」，不阻断
③ 盘点单 → 建单可无，**确认盘点结果时**硬校验
④ 固定资产 → 新建可无，**计入账（激活）时**硬校验
⑤ 所有附件校验必须在**后端**做（前端校验只是提示，可绕过）
```

## 三、附件能力补全计划

### 阶段 A：基础能力（4 张卡，约 8-10 小时）

| 卡 | 内容 | 产出 |
|---|---|---|
| **ATT-01** | **附件在线预览组件** | 新组件 `AttachmentPreview.vue` |
| **ATT-02** | 附件下载 + 权限 | 下载按钮 + 复用数据权限（谁能看哪张单据的附件） |
| **ATT-03** | 附件列表增强 | 显示大小/类型/上传人/时间；支持删除（软删）；排序 |
| **ATT-04** | `DocAttachmentPanel` 按角色分类 | 合同扫描件/补充协议/验收单分栏显示 |

#### ATT-01 在线预览（重点）

| 文件类型 | 预览方案 | 说明 |
|---|---|---|
| 图片 jpg/png/webp/gif | `<img>` + 缩放/旋转 | 直接渲染，支持滚轮缩放 |
| PDF | `<iframe src="blob:...">` 或 pdf.js | 浏览器内置渲染器够用；若需翻页/搜索再用 pdf.js |
| Office docx/xlsx/pptx | **不支持在线预览** → 显示图标 + 下载按钮 | 转 PDF 成本高，先不做 |
| 文本 txt/csv/md | 后端读前 N KB 纯文本展示 | 可选 |
| 压缩包 zip | 只下载 | — |

**实现要点**：
- 必须走 **blob URL + 带 token 的请求**（不能直接 `<img src="/api/file/xxx">`，否则 401）
- 预览模态框：左侧文件、右侧元信息（文件名/大小/上传人/时间）
- 支持多附件左右切换（上一张/下一张）

### 阶段 B：必传校验（3 张卡，约 6-8 小时）

| 卡 | 内容 |
|---|---|
| **ATT-05** | 必传规则配置表 + 后端校验框架 |
| **ATT-06** | 7 个「必须」单据接入硬校验 |
| **ATT-07** | 前端校验提示（缺附件时提交按钮禁用 + 明确提示缺什么） |

#### ATT-05 规则设计（建议方案）

```sql
-- 不硬编码在代码里（遵循「不硬编码流程」原则）
CREATE TABLE biz_attachment_rule (
  id uuid PRIMARY KEY,
  doc_type varchar(40) NOT NULL,        -- DocKind
  file_role varchar(40),                 -- 指定角色（NULL = 任意角色都算）
  required_at varchar(20) NOT NULL,      -- 'CREATE' / 'SUBMIT' / 'CONFIRM' / 'ACTIVATE'
  min_count int NOT NULL DEFAULT 1,
  max_count int,                         -- NULL = 不限
  enabled boolean NOT NULL DEFAULT true,
  remark varchar(200)
);
```

**校验点**（在后端各单据的 submit/confirm 动作里统一调用）：
```
submit      提交审批时
confirm     确认（盘点/退货）
activate    激活（资产入账）
```

**为什么做成表而不是枚举**：以后新增单据、调整规则不用改代码，符合「流程全配置化」的方向。

### 阶段 C：批量接入附件区（2 张卡，约 8-12 小时）

| 卡 | 内容 |
|---|---|
| **ATT-08** | 🔴 7 个必传单据加附件区（发票/收款/付款/报销/资产/采购退货/销售退货） |
| **ATT-09** | 🟡 6 个建议单据加附件区（合同增强/采购订单/盘点/期初/调拨/供应商/客户） |

**每张卡的做法**（已接入的 5 个就是模板）：
```vue
<DocAttachmentPanel
  :doc-type="DOC_KIND.INVOICE"
  :doc-id="detail?.id"
  :required-roles="['INVOICE_SCAN']"    ← 新增：必传角色提示
  testid-prefix="invoice-attach"
/>
```
+ 新建态：`doc-id` 为空时**不渲染上传区**（按用户指示：新建不强制），改为保存后详情页传。
  **例外**：`required_at='CREATE'` 的单据（如报销），新建弹窗内也要有上传区 → 用「先建草稿再传」的两步体验，或前端暂存。

## 四、PDF 导出计划

### 4.1 要导出的对象

| 对象 | 用途 | 优先级 |
|---|---|---|
| **业务单据**（采购订单/销售订单/合同/入库单/出库单/调拨单/退货单） | 打印签字、发给客户/供应商、归档 | P1 |
| **审批单**（含审批轨迹、每级审批人/时间/意见） | 打印留存、审计取证 | P1 |
| **工单 / 任务单** | 派工单打印、现场使用 | P1 |
| **报表**（资产负债表/利润表/现金流量表） | 财务归档、报送 | P2 |
| **附件本身** | 已有（下载即可） | ✅ 已完成 |

### 4.2 技术方案对比与建议

| 方案 | 实现 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 前端打印**（`window.print()` + `@media print` CSS） | 每张单据一个打印视图 | 成本最低、所见即所得、中文字体不用管 | 用户看到打印对话框（"另存为PDF"），不是直接落文件 | ✅ **先做这个** |
| **B. 后端生成 printpdf / typst** | Rust 库直接画 PDF | 后台批量、可直接落文件 | 中文要嵌字体、表格分页要手写、开发量大 | 后做（需要批量/邮件时） |
| **C. 前端 html2canvas + jsPDF** | 截图转 PDF | 前端可控 | 中文分页错位、大表格截断、清晰度差 | ❌ 不推荐 |
| **D. 服务端 headless Chromium** | puppeteer 渲染网页 | 渲染最准、样式复用 | 要装 Chromium（~300M）+ 内存 | 备选（若 B 不够用） |

**结论：**
```
第一步（快）：前端打印视图 → 用户 Ctrl+P / 点打印 → 浏览器另存为 PDF
第二步（按需）：如果要求「点按钮直接下载 PDF 文件」→ 上后端 printpdf
```

### 4.3 卡片拆分

| 卡 | 内容 | 估算 |
|---|---|---|
| **PDF-01** | 打印样式基础设施（`@media print` 全局样式 + 打印头/页脚/分页控制 + 单据通用打印布局） | 2-3h |
| **PDF-02** | 单据打印视图：采购订单 / 销售订单 / 合同（3 个高频） | 3-4h |
| **PDF-03** | 单据打印视图：入库/出库/调拨/退货（4 个仓库单据） | 3-4h |
| **PDF-04** | 审批单打印（含审批轨迹时间轴、每级意见、电子签名位） | 2-3h |
| **PDF-05** | 工单/任务单打印（派工单格式：任务号/负责人/期限/要求/签字栏） | 2-3h |
| **PDF-06**（可选） | 后端 PDF 生成服务（printpdf + 中文字体嵌入 + 模板 DSL） | 8-12h |
| **PDF-07**（可选） | 报表 PDF 导出 | 4-6h |

### 4.4 打印视图的设计要点

```
① 打印专用 CSS：隐藏菜单/按钮/滚动条，A4 尺寸，页边距 15mm
② 单据头：公司名 + 单据类型 + 单号 + 二维码（可选，扫码可查）
③ 表头表尾重复：长表格跨页时 <thead> 重复
④ 金额大写：人民币金额要显示大写（"壹万贰仟叁佰元整"）
⑤ 签字栏：制单/审核/批准/仓管/客户签收 —— 留空白手签位
⑥ 页码：第 X 页 / 共 Y 页
⑦ 水印（可选）："测试"/"作废" 状态时加斜向水印
⑧ 附件清单附录：单据的附件文件名列表（可选）
```

## 六、需要您拍板的三个点

1. **PDF 导出方式**：接受「点打印 → 浏览器另存为 PDF」（快、省），还是必须「点按钮直接下载 PDF 文件」（慢、需要后端生成）？
   → 我的建议：**先做前者，真需要后者再上**

2. **必传清单**：2.1 那 7 个「必须」单据，有没有要增删的？（尤其：发票是否必须传影像、报销是否必须每张票都传）

3. **Office 文档在线预览**：需要吗？（docx/xlsx 要嘛转 PDF、要嘛只能下载）
   → 我的建议：**先不做**，只支持图片 + PDF 预览
