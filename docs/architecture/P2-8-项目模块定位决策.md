## 0. 一句话结论（给老大）

**项目模块已经比评审说的强、也比评审说的弱，但强弱都不在"要不要补预算/工时"上。**

- 强在：**成员能力是齐的**（表 + 3 个接口 + 前端增删 UI），页头早就写着"项目分组"；**项目维度工时汇总也有**（预估 49.5h 真算出来了）。
- 弱在：**254 个库、526 个项目、成员行 0 条**（没有一处用过）；`actual_hours` 全是 0；**里程碑连列都没建**；**预算在项目模块里根本不该有**（ARCH-6 已把它设计成独立财务域）。
- 所以推荐 **选项 C 的修正版 C′**：**成员保留（只补演示数据）+ 里程碑做最小版单独立卡 + 预算/工时明确移交 ARCH-6 / ARCH-4**；**不改名、不降级成纯标签**（现有能力已超过标签，改名会破坏已应用的权限码/种子）。

工作量估计：**C′ ≈ 3 张 P0 卡（≈2 人时）+ 3 张 P1 卡（≈4 人时）**；A 方案 ≈ 8 卡 + 2 张新表，且与 ARCH-4/ARCH-6 撞车。

## 4. 推荐：C′（C 的修正版）——做什么、不做什么

### 4.1 做什么（P0，立即）

1. **口径收口（1 卡）**：`sys_menu` 里 `/project` 的 `name`/`title` 由「项目」→「**项目分组**」；帮助文档补一句"这是任务分组，不是项目管理系统"；项目页 hint 与菜单一致。**不动** `path/component/auth_code`。
2. **演示数据落地（1 卡）**：新增种子成员——`CP-ITER` / `DEMO-EC` 各 2 人（`admin` + `laoliu_test`，`ON CONFLICT DO NOTHING`），自检"两项目成员行 = 4"；顺带修 **460 个空壳项目**里被种子的那两个（`V0132` §1.5 已只填 NULL，重放即修复）。
3. **项目页工时明细入口（1 卡）**：统计卡旁加"工时明细 0 条 → 去登记"，点击跳 `task/detail.vue` 的 `worklog` tab；空态文案写清"实际工时靠任务工时登记汇总，明细不在项目页复制一份"。

### 4.2 做什么（P1，需老大点头后再拆）

4. **里程碑最小实现（3 卡，见 §5 K4a/K4b/K4c）**：`biz_task.is_milestone BOOLEAN NOT NULL DEFAULT FALSE` + 甘特/DTO 输出真值 + 项目页里程碑筛选。
   **前置条件**：P0 三卡上线并观察 ≥1 周（若成员仍 0 使用，说明连"分组"都没跑起来，里程碑继续压后）。

### 4.3 明确不做（写死，防止后面被"顺手补上"）

- ❌ 项目模块加 `budget` 列 / 预算页 / 预算控制点 → **ARCH-6**（`biz_budget*`）。
- ❌ 项目模块建 `project_worklog` / 项目工时归集表 / 按人成员工时矩阵 → **ARCH-4 MES 工作量计量**（`biz_work_log*`）。
- ❌ 项目成员 = 任务可见性（扩权）→ 永远不做（P04 测试在守）。
- ❌ 改名"项目标签" / 删成员 UI / 删统计卡 → 负收益。
- ❌ 重命名 `business:project:*` 权限码、改 `/project` 路由 → 破坏已应用迁移与角色种子。
