## 1. 执行摘要（一页纸）

### 1.1 这套系统现在能干什么

**一个模块化、可二开的 ERP 底座，业务主链在国内中小制造/贸易企业的「订单—库存—账务」层面是通的。**

- **13 个业务域、90 个页面**在 145 真机走过**真实 HTTP + 真实落库 + 跨表勾稽**，累计 **3 034 条断言 0 FAIL、130+ 组勾稽 0 差异**（明细见 §2）。
- 核心闭环**端到端可用**：采购（申请→询比价→订单→审批→收货→应付→付款→退货）、销售（订单→发货→出库→应收→收款/退款→开票→退货→佣金）、库存（仓库/库位/序列号/期初/调拨/盘点/出库，五本账同源）、财务（凭证→总账→试算→三大报表→月结/年结）、资产（建卡→折旧→处置→作废）、预算（编制→占用→执行→超支拦截）、合同（四类型→审批→履约→提醒）、审批引擎（会签/或签/比例、驳回四目标、委托、自审监控、ARCH-8 五层降级）、任务协作、附件与 PDF（14 个导出入口）、平台功能（导入导出/字典/参数/日志/定时任务/在线用户/巡检/存储/帮助）。
- **数据一致性在「产品逻辑」层是闭合的**：全库凭证借贷平衡 0 张不平；试算平衡 借=贷=7 952 100.00；资产=负债+权益；利润表净利润=权益变动；现金流量表期末=货币资金；库存=流水（自有数据 0 差异）；三级勾稽（订单→入库→应付）金额逐单相等。
- **工程质量高于常见中台**：279 条迁移（最高 `V0357`，带指纹校验）、154 张表、15 道提交门禁、**3 880 条后端单测（本卡修复后 3 880 全绿）**、93 个前端单测文件、179 篇文档（6.1 MB）、`pnpm typecheck` RC=0。**但门禁在 HEAD 上是「该红没红」的状态**：`cargo clippy --all-targets -- -D warnings` 直接红 3 处（`invoice.rs:1903` / `receivable.rs:782` / `sales_order_model.rs:661`），`cargo fmt --check` 在 3 个文件上有 diff —— 说明最近有提交绕过了 `scripts/check.sh`（见 §5.7）。

### 1.2 现在不能干什么（诚实清单）

1. **不是「生产就绪」，是「可交付试运行」**。加权总分 **3.5 / 5**（详见 §5），距「直接给客户用」还差三件事：**运维兜底（无数据库备份/恢复流程、无告警）、1 个 P1 缺陷（库存巡检会改错账）、以及两个整块缺失的 ERP 能力域（生产制造、人力资源）**。
2. **一处 P1 未修**：库存巡检（`GET /erp/inventory/audit`）对「一物一码多桶」物料报**假差异**，且 `dry_run=false` 的修复路径会**抹掉库位桶的库存**（E2E-03 ISSUE-01，已定位到 `inventory_audit.rs` 的 `COALESCE(MAX(qty) FILTER ...)`）。这是本次评审**唯一一条「会造成数据损坏」的已知缺陷**。
3. **共享演练库的数据已污染到「全量巡检不可信」的程度**：`cloudpivot_dev` 上 80 项不变量有 **20 项红（12 BLOCKER）**；同套检查在干净库 `cloudpivot_fresh` 上 **78/80 绿，只剩 2 项**（其中 1 项是真实种子缺陷 H6）。也就是说：**红的多数是历史演练残留，但「演练库」本身已经不能当作验收证据**。
4. **前端有 2 个死菜单**（`价格查询`、`收款退款单`，`path` 为空、无页面、无路由），其中**收款退款单后端 API 完整、前端整块缺失**（E2E-02 只验了 API）。
5. **单据明细上限 200 行**（`MAX_LINES=200`，实测 10 000 行直接 400）——「1 万行明细单据」在设计上不成立；大数据量只能走导入/导出通道（实测 1 万行导入 509 ms、入库 880 ms、导出 880 ms）。
6. **运维面缺口**：生产**没有数据库备份脚本**（全仓只有 p0 修复脚本里的临时 `pg_dump`）；`/metrics` 默认关闭（145 实测 404）；无告警通道接入；日志只有 journald 本地文本。

### 1.3 最大的三个风险（按「造成损失的可能性 × 严重度」排序）

| # | 风险 | 证据 | 后果 |
|---|---|---|---|
| R1 | **库存巡检的「修复」会改错账** | E2E-03 ISSUE-01：`book=2 / actual=5 / diff=-3`；`dry_run=false` 把账面改成汇总桶值 | 财务/仓管照着巡检点「修复」，会**不可逆抹掉**库位桶库存（需人工回修） |
| R2 | **无生产备份与恢复演练** | 全仓无 `pg_dump` 定时任务/脚本；`deploy.sh` 只备份构建产物 | 一次误操作/磁盘故障 = 账套丢失；客户数据无法承诺 RPO/RTO |
| R3 | **会签（ALL）节点缺人 = 单据永久卡死** | E2E-01/E2E-06/E2E-07 三张卡都撞上：`p3a_0003` 等失效账号在 `PURCHASE_MANAGER / DEPT_LEADER` 全局角色里，少一票就停在 `PENDING_APPROVAL`，无超时、无 HTTP 终止入口（`409/65023`「请联系流程管理员终止」但**没有该接口**） | 演示/生产都可能出现「单子永远批不完」，只能改库 |
