## 1. 一、作废不退序列号 —— 代码修复

### 1.1 根因

`stockin_handler::cancel_in_tx` 的 `POSTED → CANCELLED` 分支（P9 补齐 7 步）**没有序列号这一步**：
一物一码物料的号由过账事务（`post_in_tx` 第 ④ 步 → `stockin_model::insert_serials`）写成
`source_type='PURCHASE' AND source_id = 收货单 id`，作废后这些行依然是 `IN_STOCK`。
后果正是卡面说的 W2c 口径：`serial_model::recompute_quantity` 派生的「在库件数」与
`biz_inventory.qty`（作废后已减）对不上。

### 1.2 口径选择（卡面 §一 三选一 → 取 ②+③ 组合，不猜）

先查约束：`ck_biz_material_serial_status` 只允许 `IN_STOCK / OUTBOUND / SCRAPPED` —— **没有 `VOID`**。

| 方案 | 判断 | 理由 |
|------|------|------|
| ① 加 `VOID` 状态 | 不采纳 | 要动迁移 + `serial_model::ALL_STATUSES` + 合法边表 + 前端状态映射 + 序列号分页筛选，为一个「从未出库的单据作废」付这份代价不值 |
| ② 未出库 → 删/软删该单生成的号 | **采纳（软删）** | `uk_biz_material_serial_no` 是 `WHERE deleted_at IS NULL` 的部分唯一索引：软删后同号可被重新贴用（W2a 口径），审计痕迹不丢；**物理删不行** —— `biz_stock_transfer_item_serial.serial_id` 是硬外键 |
| ③ 已出库 → 拒绝作废（409） | **采纳** | 与「货已部分出库」同款语义：件已经离开仓库，只能先做退货入库冲销。判据用**序列号状态**而不是库存数量 —— 同一物料后来又进过别的货时数量上「够退」，退回来的却不是本单那几件 |

落地：`stockin_model::void_serials_of(ex, 收货单 id, in_no, operator, now)`

1. `lock_serials_of` 先 `SELECT … FOR UPDATE` 锁本单的号（并发：作废与单品出库改同一行 `status`，靠行锁串行）；
2. 任何一条 `status <> 'IN_STOCK'` → `DbError::InvalidValue("SERIAL_SHIPPED|…")`；
3. 全部在库 → `UPDATE … SET deleted_at = now(), update_by = ? WHERE source_type='PURCHASE' AND source_id = 本单 AND status='IN_STOCK' AND deleted_at IS NULL`。

`cancel_in_tx` 把它放在**库存冲减之前**（第 ② 步），这样一物一码物料报的是
「序列号 SN-… 已出库」，而不是笼统的「库存不足」；`cancel_write_error` 增加第三个哨兵分支
（`CancelGuard::Shipped / Detail`），三类拒绝都是 `409 + 可执行文案`。

## 2. 二、`M-W1A-004` 的真实来源（先查清，再动手）

### 2.1 11 条序列号从哪来

| 证据 | 结果 |
|------|------|
| 该物料在 `biz_stock_in_item` / `biz_purchase_order_item` 里的行数 | **0 / 0** —— 从来没进过采购、没有任何收货单 |
| `biz_material_serial.source_type` / `source_id` | 11 条全是 `PURCHASE` + **`source_id IS NULL`** |
| 全仓只有两个写序列号的地方 | `serial_model::batch_generate`（`POST /business/erp/serial/batch-generate`，**可以**不写 `source_id`）与 `stockin_model::insert_serials`（**必定**回填 `source_id = 收货单 id`） ⇒ 这 11 条**只能**来自「批量生成接口」的验收夹具 |
| `biz_inventory_txn` | 只有 `SERIAL_IN 3（doc_type=SERIAL_BATCH，doc_no=SN-20261030-000009）`、`SERIAL_OUT 1`、夹具调拨 `TK-20261030-000001` 的 `TRANSFER_IN/OUT 2`（`unit_cost 10` 是手工填的） |
| 号段 | `biz_seq(SN, 20261030) = 11`，与 11 条行一一对应 |

⇒ **没有真采购来源**，卡面 §二 第 3 条（补做收货单）不适用：补一张没有供应商/价格/合同依据的
采购单才是造账（P9 §7 也是这个判断）。

### 2.2 卡面「8 条 IN_STOCK 与在库 2 对不上」是**未过滤软删**导致的误判

```
-- 卡面/交接用的统计（漏了 deleted_at）
select status, count(*) from biz_material_serial …  →  IN_STOCK 8 / OUTBOUND 2 / SCRAPPED 1
-- 正确口径
select status, count(*) … where deleted_at is null →  IN_STOCK 2 / OUTBOUND 1              （存活 3 条）
```

那 8 条（`SN-20261030-000001…000008`）在 **2026-10-31 00:53:50** 已被批量软删（`deleted_at` 非空、
`updated_at` 同刻）。按存活口径，`IN_STOCK 2`（都在 WH01）= `biz_inventory(WH01).qty 2`，**本来就是自洽的**。

所以本卡新增了不变量 **C5「一物一码：在库序列号件数 = 库存数量」**，统计里**强制**带
`AND deleted_at IS NULL`，并在注释里写明这次的误判，避免下次再用错口径白开一张卡。

### 2.3 剩下的真问题：C3（2 件、0 元、0 均价）

`M-W1A-004 / WH01` 有 2 件、`amount = 0`、`avg_cost = 0`（P9 把无单据的 20 元价值归零后必然命中 C3）。
要让 C3 转绿只有两条路，P9 §7 已论证过都不该走：

- 给这 20 元补凭证 → 没有供应商/应付可挂，等于凭空造账，且立刻打破 B3；
- 给库存加钱 → 打破 B2（`biz_inventory.amount` 435 必须等于 1405 净额 435）。

本卡走**第三条路：把这条无单据夹具链整段清掉**（卡面 §二 第 2 条「若是验收夹具 → 清理」）：

| 表 | 动作 | 行数 |
|----|------|------|
| `biz_material_serial` | **软删**存活 3 条（`SN-…000009/000010/000011`） | 3 |
| `biz_inventory_txn` | 物理删夹具流水（`SERIAL_IN 3` / `SERIAL_OUT 1` / `TRANSFER_IN 2` / `TRANSFER_OUT 2`） | 4 |
| `biz_inventory_location` | 物理删（WH01 未分配库位桶 2） | 1 |
| `biz_inventory` | 物理删（WH01 2 件 0 元 / WH02 0 件均价 10 的残行） | 2 |
| `biz_stock_transfer` / `_item` / `_item_serial` | **不动**（单据与审批历史保留；`serial_id` 指向软删号，FK 与审计都在） | 0 |
| `biz_seq` | **不动**（号段只前进不回退） | 0 |

为什么流水/账也要删（而不是留 2 件 0 元）：
`B4 流水累计 = 库存`、`B1 库位账 = 成本账`、`E4 库存 ≤ 有效入库+调拨/序列号净入` 是三条硬等式，
只要把「数量」清零就必须把「解释这个数量的流水」一起清 —— 否则删了库存行、流水还净入 2，B4 立刻 BLOCKER。
**不写反向流水**：反向流水是给「有单据的真实业务」用的，这条链从来没有业务。

### 2.4 两道安全阀（脚本里 `RAISE EXCEPTION`）

1. 该物料一旦有 `biz_stock_in_item` / `biz_purchase_order_item` 行 → **中止**（说明货有来源，应补做收货单）；
2. 该物料库存 `sum(amount) <> 0` → **中止**（说明价值已有账载，删数据会丢钱）。

## 5. 不变量套件的变化

新增 **C5「一物一码：在库序列号件数 = 库存数量」**（`账实`，WARN）：

- 每个 `(物料, 仓库)` 的 `count(serial WHERE status='IN_STOCK' AND deleted_at IS NULL)` 必须等于
  `biz_inventory.qty`（按 `(物料, 仓库)` 汇总，库位维度先 `sum`）；
- `warehouse_id IS NULL` 的序列号按「(无仓库)」单独报 —— 它进不了任何一本仓账
  （`batch-generate` 不带 `warehouse_id` 就会造出这种号，`link_inventory` 只留一条 WARN 就跳过）；
- 级别 WARN 不 BLOCKER：`serial_required` 可以在已有库存的物料上后开（W1c 允许 `PUT`），
  那会出现「历史按数量的库存 vs 0 条号」的过渡态，需要人看而不是停机。

套件条数因此 28 → 29（P9 交付时 27/28 是同一批检查，本卡新增 1 条）。
