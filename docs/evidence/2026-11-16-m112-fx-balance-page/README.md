要点：**原币 × 期末牌价 = 折算**（100 × 7.2 = 720），**折算 − 账面 = 差额**（720 − 710 = 10，文案「调增 10.00」）。
所以「USD 建单 7.1、期末 7.2」这段汇率变动，在页面上就是一行 10.00 的未入账汇兑差额 —— 与 M1-05 期末调汇会调的金额同源。
合计行的原币列写「原币跨币种不相加」（跨币种的原币相加是错账，页面显式拒绝）。

## 四、新增门禁：`frontend/tests/unit/m112-fx-balance-page.test.ts`（14 条）

| # | 断言 | 为什么必须钉 |
|:--:|:--|:--|
| 1 | 路由 `path` / `component` / `meta.permission` 三处与 `V0412` 逐字一致 | 漂了就是点菜单 404 / 403 |
| 2-3 | API 层路径写全 `/api`；`close_rate` / `converted_base` / `reval_diff` / `total_*` 类型是 `string \| null` | 漏 `/api` 会命中 SPA fallback；`null` 写成 `string` 就会有人补默认值 |
| 4 | 折算列**两处**都必须用 `amountCell(...)`，且**不许**出现 `formatAmount(row.converted_base)` | 换成 `formatAmount`：`null` → 空串 → 被补 `0.00` |
| 5 | 差额列用 `diffText` / `diffTotalText` | 正负要说「调增/调减」，`null` 要「—」 |
| 6 | KPI 折算合计用 `convertedTotalText` | 半套折算的合计绝不能出数 |
| 7 | 缺牌价告警有 `v-if="missingRateMessage"` + `data-testid`；文案里必须出现「没有按汇率 1 折算」 | 告警是这条口径的唯一出口 |
| 8 | 模板/脚本**没有** `toFixed(`、没有 `* row.close_rate`、没有按 1 折算 | 前端一旦自己折算，就与后端两套真相 |
| 9 | 明细表 14 列列名逐字固定 | 悄悄少一列 = 报表静默缺口径 |
| 10 | 汇总段 + 合计行 + 「原币跨币种不相加」 | 跨币种原币相加是错账 |
| 11 | 账面口径列带 `basisLabel` + `basisHint` tooltip | 多币种科目退化时要能解释「这不是整科目账面」 |
| 12 | 空表文案走 `emptyText`（区分「本位币」「该币种无业务」） | 空表说错话比报错更误导 |
| 13-14 | 逻辑边界：`-0.0001` 算贷、`-0` 算平；`''`/`null` 进「—」而真 `0.0000` 仍显示 `0.00` | 与后端 `side_of` 同口径 |

**变异反证（证明门禁真的会红，不是摆设）**：

```
sed -i 's/amountCell(row.converted_base)/formatAmount(row.converted_base)/' .../index.vue
npx tsx --test tests/unit/m112-fx-balance-page.test.ts
  → not ok 4 - 折算列：模板必须用 amountCell（null → 「—」），不许用 formatAmount（null → 空串）
  → # pass 13 / # fail 1
还原后：pnpm test:unit → 1933 passed / 0 failed
```
