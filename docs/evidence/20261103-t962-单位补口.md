# 单位止血补口（DC-09 缺口 1/2）— 过账结算复检 + 物料主数据禁选折算单位

- 卡：`t_962a5f84`【ERP-P2】单位止血补口：过账/结算复检单位 + 物料主数据禁选折算单位
- 来源：`t_d594ede3`（DC-09，`81ada35`）交付时登记的**两个已知缺口**（见
  `docs/evidence/20261102-dc09-单位止血.md` §6 第 2、5 条）
- 基线：`21e3297`（内控把审批人排除到 0 人时发起即失败）
- 结论：**写账的两个入口（收货过账 / 调拨结算）按明细快照复检单位；物料主数据只能挂基本单位**。
  生产 144 存量命中 **0 行**，本卡上线不冻结任何现网物料。

## 1. 缺口与修法

| 缺口 | 症状 | 本卡修法 |
|---|---|---|
| ① **过账 / 结算不复检单位** | DC-09 只在建单 / 改单拦了单位；`PATCH /business/stock-in/{id}/status=POSTED` 与调拨「收货」结算不查 `is_base` ⇒ 升级前建的折算单位草稿（或绕过接口 `UPDATE biz_stock_in_item.unit_id` 的单）仍能过账，`qty` 直接进三本账 | `unit_guard::ensure_unit_row_is_base(ex, unit_id, material_id, line_no, qty)`（按**明细快照的 `unit_id`**）+ `ensure_base_unit_in(ex, …)`（调拨明细无 `unit_id` ⇒ 按物料单位），非基本单位 → `400 + 66030` |
| ② **物料主数据仍可挂折算单位** | `biz_material.unit_id` 能指向 `is_base = 0` 的单位 ⇒ 该物料**任何单据都被 400 拒**，用户只看到「这个物料的单建不了」 | `unit_guard::ensure_material_unit_is_base(is_base, unit_name)`，在 `material_create` / `material_update` 解析 `unit_id` 之后调用 |

### 报文（逐字）

写账期（明细快照，物料编码可得时）：

```text
items[0] 物料 P2B1-M1：单位「箱」不是基本单位：本版本不支持多单位换算，请按基本单位录入（1 箱 = 12 个 → 录 24）
```

物料主数据：

```text
物料的计量单位必须是基本单位：折算单位（箱/打）只能用于显示，本版本单据不支持多单位换算（当前「箱」）
```

- HTTP `400`，`code = 66030`（复用 DC-09 的专用码，不新增码表项）；
- `items[i]` = 明细行下标（0 起，与文档行序一致；写账期用的是**明细的落库顺序**，不是请求体）；
- `→ 录 24` = 本行 `qty × rate`（4 位四舍五入）——用户照抄就能过。

## 3. 三道闸的分工（为什么缺一不可）

```text
① 建单 / 改单期  ensure_base_unit      判「物料现在的基础单位」   采购 / 收货 / 调拨
② 过账 / 结算期  ensure_unit_row_is_base 判「明细快照的 unit_id」  收货过账（两条入口）/ 调拨结算
                （调拨明细无 unit_id ⇒ ensure_base_unit_in 按物料判）
③ 物料主数据    ensure_material_unit_is_base                    material_create / material_update
```

- ① 挡不住「绕过接口 `UPDATE`」与「升级前建的草稿」：明细 `unit_id` 是快照，物料侧再怎么看都看不出问题；
- 反过来物料建单后被改成基本单位，也不代表这行 `qty` 是按基本单位录的 —— 所以 ② 必须判**快照**；
- ③ 把「建出来的物料任何单据都 400」这种死路堵在源头。

### 一个顺带收口

DC-09 §6 第 4 条说「复制收货单沿用原单 `unit_id` 快照、不过闸」。本卡之后**复制出来的单在过账时会被 ② 拦下**——
不需要给 `copy_stock_in` 单独加闸（加了也只是提前报错，不改口径）。

## 7. 已知边界（刻意不做）

1. **不做换算**（方案 A：`qty_base = qty × rate`、三本账只用基本单位）仍属专项；本卡只保证
   「折算单位进不了账」。
2. **调拨明细没有 `unit_id` 列**（DC-09 已实测，卡面写错）：调拨侧的写账复检只能按
   **物料当前的计量单位**判 —— 与建单期同一判据、同一文案，只是执行时机挪到结算前。
3. **物料主数据的 Update 按「解析后的有效单位」判**：存量挂在折算单位上的物料**不改单位也不能保存**
   （要先把单位改回来）。这是卡面要求的行为（生产 0 行），已用单测钉住。
4. **只恢复「能不能写账」，不恢复「该不该作废」**：已过账的历史单据不受影响（本卡不回溯）。
5. 复制收货单 / 复制调拨单不单独加闸：它们抄的是原单快照，过账 / 结算时由 ② 兜住。
