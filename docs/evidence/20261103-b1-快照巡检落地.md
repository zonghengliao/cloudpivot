## 9. 告警接线（未完成的部分，留给 B2）

`notice::dispatch`（`backend/src/business/notice/mod.rs:290`）是 **in-process 的 Rust 函数**：
要连接池、模板渲染、收件人扇出、SSE 推送，**没有 CLI 入口**；后端也没有「跑一条 SQL 巡检」的
子命令。cron 里唯一能触达它的路径是 `POST /api/business/notice/send`，但那需要登录 token 且
实例在线 —— 本机当前没有 8023 实例在跑（`ss -ltnp | grep 802` 空），无法端到端验证，
所以按卡面「退而求其次」执行：

- 有 BLOCKER：写 `/var/log/cloudpivot/snapshot-audit.log` + 写 JSON 结果文件
  `/var/log/cloudpivot/snapshot-audit.latest.json`（含 `summary` 与 `checks[].rows[]`），
  并通过 `--notify-cmd` 钩子把 `SNAPSHOT_AUDIT_JSON / SNAPSHOT_AUDIT_BLOCKERS / SNAPSHOT_AUDIT_SUMMARY`
  传给外部命令（实测：钩子被调用、环境变量正确、钩子失败不影响退出码）。
- 只有 WARN：只写日志，不打扰人（`notify` 只在 `blocker>0` 或某条巡检执行失败时调用）。

B2 接线方式（改 `/etc/cloudpivot/snapshot-audit.env` 一行，不动巡检脚本）：

```
SNAPSHOT_AUDIT_NOTIFY_CMD='curl -sS -m 10 -X POST "$CLOUDPIVOT_API/api/business/notice/send" \
  -H "Authorization: Bearer $CLOUDPIVOT_TOKEN" -H "Content-Type: application/json" \
  -d "{\"title\":\"快照一致性告警\",\"content\":\"$SNAPSHOT_AUDIT_SUMMARY\",\"level\":\"ERROR\"}"'
```
