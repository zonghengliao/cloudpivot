# P3-07「执行付款」判据：按钮可见性 + 实例详情请求次数（2026-11-08T04:29:17.424Z）
说明：那 1 发 instance 详情是**审批进度块**（P17 既有行为）自己发的；
     兜底探针若另发一次，A 会变成 2 次 —— 所以「A 也是 1 次」= 探针复用了进度块的缓存，零额外请求。
A. 真后端（无 awaiting_executor，走实例状态兜底）: 按钮=可见 · instance 详情请求 1 次（1 个不同实例）
B. 拦截详情接口补 awaiting_executor=true: 按钮=可见 · instance 详情请求 1 次（1 个不同实例）
C. 拦截详情接口给 awaiting_executor=false（后端否决）: 按钮=不出现 · instance 详情请求 1 次（1 个不同实例）
结论：A/B 按钮出现、C 按后端字段消失；三态都只 1 发实例详情 ⇒ 兜底探针零额外请求 ✓

（B/C 是 `page.route` 拦截层，仅用来模拟「后端已下发 awaiting_executor」的将来态，
  不当真机数据用。脚本：`raw/count_requests.mjs`，2026-11-08 实测。）
