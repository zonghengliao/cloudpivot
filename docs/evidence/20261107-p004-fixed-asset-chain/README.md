### 金额勾稽

- 月折旧额 = (原值 − 残值) / 使用月数：A `(120000−6000)/60 = 1900` = 系统 1900.0000（差 0）；B `(1000−50)/3 = 316.6667` = 系统 316.6667（差 0）→ **是**
- 每期折旧凭证金额 = 该期 `biz_depreciation_batch.total_amount` = Σ`biz_depreciation.amount`：5/5 期全部相等（2216.6667 / 2216.6667 / 2216.6666 / 1900 / 1900）→ **是**
- 卡片 `accumulated_depreciation` = Σ 已过账明细（巡检 K2）：A 9500 = 9500、B 950 = 950 → **是**
- 净值恒等 `net_value = original_value − accumulated`：2/2 台成立（库层 `ck_biz_fa_net` 亦兜底）→ **是**
- 累计折旧不超可折旧总额：2/2 台 `accumulated ≤ depreciable_base`；B 提足后连续 2 期不再计提 → **是**
- 凭证借贷平衡：全账 **29 张全部平衡（0 张不平）**；折旧 5 张（借 5602.01 = 贷 1602 = 10450）、处置 6 张、购入 2 张逐张 `total_debit = total_credit = Σ明细`→ **是**
- 处置损益：A 净损 `110500 − 100000 = 10500` → 5711 营业外支出 10500；B 净益 `60 − 50 = 10` → 5301 营业外收入 10；1606 固定资产清理净额 **0**（归零）→ **是**

## 二、发现的问题

| # | 问题 | 严重度 | 复现步骤 | 建议 |
|---|---|---|---|---|
| 1 | **FIXED_ASSET 触发点「接线了但没规则」**：`spec::TRIGGER_SPECS` 标 FIXED_ASSET `wired=true`，代码三处 hook（stop/enable、处置、作废处置）都在跑，但迁移全集跑完后 `biz_flow_linkage_rule` **0 条 FIXED_ASSET 规则** ⇒ 停用/启用/处置默认**一条通知都不发**，且无任何报错（典型「看起来配好了」） | P2 | 全新库 → 停用资产 → `select count(*) from sys_notice where biz_type='FIXED_ASSET'` = 0；补配 `PUT /api/business/flow/linkage`（IDLE/IN_USE/DISPOSED + SEND_NOTICE, confirm=true, recipient=CREATOR）后再停用/启用/处置 → 各发 1 条，幂等键按事件维度（同一事件重放不重发、可逆边第二次照发） | 仿 V0254 补一条预置迁移（3 条 FIXED_ASSET SEND_NOTICE），或在「上线清单/资产模块文档」里写明「资产通知需先配联动规则」；建议前者（空表 = 能力不存在，V0254 的原话） |
| 2 | **处置当月漏提折旧**：`asset_compute` 头部写明规则②「当月减少当月照提，筛选 SQL 用 `disposal_date >= 期初`」，但 `asset_model::scan_assets_for_period` 的状态条件是 `status IN ('IN_USE','IDLE')`，**DISPOSED 被整类排除** ⇒ 月中处置的资产当月一个月折旧提不到（本例 A 若 6 月处置：按代码口径扫描命中 0 台；放宽状态后应命中 1 台 / 1900） | P2 | `select count(*) from biz_fixed_asset where status in ('IN_USE','IDLE') and disposal_date >= date '2026-06-01' and coalesce(last_depreciation_period,'') < '2026-06'` → 0，把状态集加上 DISPOSED → 1（`09_verify.sql` ⑤ 两列并排） | 不能只改扫描：处置凭证已按处置时点累计额落账，事后补提会让卡片缓存与凭证脱节。建议**二选一定口径**后写死：①处置前置校验「处置当月的折旧批次必须已过账」→ 409 提示先计提（推荐，最小改动、不动账务口径）；②扫描纳入「本月处置」的卡片，且处置凭证延后到期末折旧后再出（改动大，需财务确认） |
| 3 | **卡面接口契约与真实 API 不一致（照抄 curl 会静默出错）**：卡面写 `useful_life / residual_rate / start_date`、`price`、`status=NORMAL`、`/disable`、`/enable`；真实契约是 **年限/残值率由 `category_id` 带出**（`CreateAssetReq` 无这三个字段，serde 忽略未知字段 ⇒ 传了也不生效、不报错）、处置字段为 **`sale_price`/`output_tax`**、状态枚举是 **`IN_USE`**、停用/启用是 **`POST /asset/{id}/status {target_status}`** | P3 | 按卡面 body 提交 → 200 成功，但年限/残值率取分类值（`biz_fixed_asset.useful_life_months` 仍为分类的 60），`price` 被忽略导致售价 0 | 演练卡模板按 `asset_dto.rs` 的请求结构写；或后端对资产建卡开启 `deny_unknown_fields`（会影响既有前端，需评估） |
| 4 | 卡面「折旧凭证 借 1900 / 贷 1900」在**多台同部门**时是汇总一行（2216.6667），单台金额只能从 `biz_depreciation` 明细看 | P4 | 同一部门两台资产同期计提 → 借方 1 行 = 两台之和（`§5.5.3` 设计） | 非缺陷，汇报/对账口径需按「明细核对 + 凭证总额核对」两步走 |
