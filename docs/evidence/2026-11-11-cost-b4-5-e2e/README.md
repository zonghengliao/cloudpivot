## 覆盖的链路与断言（9 步 / 78 条，全绿）

| 步 | 做什么 | 断言（判据全部来自**库里的真实数据**，不看接口自报） |
|---|---|---|
| 1 准备 | 建 DRAFT 批次（真实接口）+ 装输入侧夹具 | 成本对象 / 领料单 / 工时 1 条 / 费用 2 条 / 分摊规则 2 条 |
| 2 calc | 六段真实代码：料 → 工 → 费 → 池对账 → 分摊 → 计算单 | 料 19000 / 工 4000 / 费 4000 / 完工 **22311.1104** / 在制 **4688.8896** / 单位 27.888888 / Σ分摊 = Σ池行 |
| 3 审 | 提交 → 财务经理 → 财务总监（真实审批引擎） | SUBMITTED、实例 `COST_SETTLE/批次`、两级待办各自消化、APPROVED、实例留痕 |
| 4 结算 | 真实接口（一个事务） | 入库单 `PRODUCTION/POSTED` 800 件 22311.1104 且回填完工凭证；**三本账**（流水 `PRODUCTION_IN` / 库存账 / 库位账）数量与金额一致；结算凭证 **4 张**全 POSTED 且各自借贷平衡；`4001.01/.02/.03` 余额 3800 / 444.4448 / 444.4448；`4101.01/.02` 清零 |
| 5 对平 | `erp_invariants.py --group 成本` | **C-COST-1~6 共 8 条检查 8/8 通过、BLOCKER 0、WARN 0、exit 0** |
| 6 红冲 | 真实接口 | 批次 REVERSED + 原因落库；入库单 CANCELLED；计算单回 CALC；**4 张红字凭证** POSTED、原凭证全部 `reversed_by`；库存回 0（流水 `PRODUCE_CANCEL`）；`4001.02/.03`、`4101.01/.02` 净额归零，`4001.01` 剩 19000（领料凭证属上游单据，不该被成本红冲带走）；巡检仍 exit 0 |
| 7 重算 | 红冲后重算 | **同期间能建新批次**（排除 REVERSED 的唯一键生效）、**第二张活跃批次被 409+66072 拒绝**（不是放水）、重算金额与第一轮一致 |
| 8 再结算 | 第二轮提交 → 两级审批 → 结算 | SETTLED、入库 22311.1104、库存回 800 件 / 22311.1104、4 张凭证、巡检 exit 0 |
| 9 收尾 | 清场 | 残留 0 行 |

## 造错模式（验收「失败时输出可定位」）

两个场景，都是**先注入缺口 → 结算必须被指定断言拦下 → 修好后同一张单能重试成功**：

| 模式 | 注入 | 实测拦截报文（节选） | 修复动作 |
|---|---|---|---|
| `bypass4101` | 有人绕过成本模块手工记一笔 4101.01 100（ARCH-9 R-3） | `409 + 66065`：`费用池与总账 4101.* 借方发生额对不平（期间 2026-11，结算口径）：池 4000，应已入账 4000，账面 4100，差额 -100…｜E2E 演练车间 / 4101.01：池 3000，账面 3100，差额 -100｜凭证：E2E-V-INJ-0001、PZ-…` | 删掉旁路凭证 → 重试结算 200 |
| `drop_material_voucher` | 领料凭证缺失（料钱没进在制） | `409 + 66077`：`结算事务断言 C-COST-3「4001 本期净发生 = Σ(期末在制 − 期初在制)」不平…4001 本期净发生 -14311.1104 / Σ(期末在制 4688.8896 − 期初在制 0.0000) = 4688.8896；差异 -19000.0000` | 补回领料凭证 → 重试结算 200 |

两个场景都额外断言：**失败时零写入**（无入库单、无结算凭证）、**批次仍是 APPROVED（不留死单）**、
修好后巡检 exit 0 —— 对应 AGENTS 约定 11（事务失败必须能重试，不许留死单）。

## 已知缺口 / 发现（**卡外**，未动）

1. **`POST /business/erp/cost-period/calc` 编排接口未落地**（设计 §5.2 #27，属「编排卡」）。
   六段目前只有库内函数（每个模块头都写着「没有 HTTP 入口，这是有意的」），前端 `cost-period.ts`
   也把 `calc()` 位置留空。本卡的演练用 `backend/examples/cost_calc_probe.rs` 按各模块文档约定的
   顺序调用**同一批函数**跑真代码；接口上线后把 `.sh` 里那一行换成 curl 即可，其余不动。
   **建议另开卡**补 #27（编排 + 事务边界 + 接口 + 前端 `calcCostPeriod()`）。
2. **`APPROVED` 状态没有回退边**（`state_machine::COST_PERIOD_EDGES` 只有 `APPROVED → SETTLED`）。
   实测：结算因「分摊结果被删」失败（`409 + 66077`）后，`撤回` 被拒（`66073`：只允许 `SUBMITTED` 撤回），
   重算分摊也被拒（`66066`：`APPROVED` 不允许重算分摊）⇒ **产品上没有回头路**，只能删分摊结果之外
   的办法改库。属 B3-1（状态机）/B3-6（结算）范围，本卡未动，已报出（同 AGENTS 约定 11 的死单风险）。
   规避：造错模式因此选「外部数据可修」的两个场景（旁路凭证 / 领料凭证），不依赖批次状态回退。
3. `V0381__cost_flow_def.up.sql` 漏 `is_system` 使巡检 H6(BLOCKER)/H5(WARN) 恒红（B3-10 已报），
   本卡未动；本卡的「对平」只跑 `--group 成本`，不受影响。

## 环境事实（踩过的坑，都已在脚本里兜住）

- **空库首启**：`createdb` 后由实例自动迁移（约 30–60s，315 个迁移）；从 template 克隆的库会因
  迁移指纹校验失败（`数据库迁移失败: query failed`），所以脚本一律建**空库**。
- **配置目录按 CWD 解析**：必须 `cd backend/` 再起实例，否则读不到 `config/config-test.toml`
  → `database.enabled` 落回默认 false → 实例起来但没连库（`数据库未初始化`）。
- **端口残留会让 health 探针误判就绪**（旧实例答 `/health`、新实例还在迁移 → 演练对着没建表的库跑）。
  脚本现在：起实例前先清端口 + 就绪判据追加「`sys_dept` 表存在且有行」，并把 pidfile 改写成
  **真正监听的那个 pid**（`nohup` 包装进程比服务进程早一号，记错杀不掉）。
- 演练期间的会计期间必须是 OPEN（脚本默认取当月；种子库 2026-01~12 全 OPEN）。
