## 1. 每月结转凭证 —— **本仓月结不做损益结转（设计如此），结转凭证只有年结一张**

卡面 ② 期望「月结后损益类科目余额 = 0」。实测 **不成立**，原因不是 bug 而是口径：

* `period::close_period` 只做四项校验 + 封账（+ 期末外币重估），**不生成任何结转凭证**；
* 月结后 11 月末损益类科目净额为 **贷方 12 211.30**（`raw/t1_pl_balances.txt`），3103 本年利润余额 = 0；
* 设计依据：`docs/ERP-批次1-产品需求PRD.md:817`「期初一律取累计净额，不做上月期末结转的物理动作」；
  利润表的「本期 / 本年累计」按发生额现算（`income_statement` 只取发生额，不取余额），
  资产负债表的未分配利润把 `@CATEGORY:PROFIT_LOSS + 3103 + 3104` 一起归并（`UNDISTRIBUTED_PATTERN_FALLBACK`），
  所以**报表口径在月结后依然自洽**（见 §3 的资产负债表 91 300 = 79 088.70 + 12 211.30）。

结论：这套设计把「结转」这一个物理动作推迟到年结，规避了 12 次物理结转带来的「补录上月凭证 → 下月期初错乱」。
**代价是「月末损益类余额 = 0」这条验收口径在本仓不成立**，判据要换成：
(a) 利润表净利润 = 损益类科目净额；(b) 资产负债表平衡；(c) **年结后**损益类余额归零。三条都已在 §3/§4 断言。

## 7. 演练发现的问题

### F1（P2，已修，`7591405`）已年结的年度许可单独反结账 ⇒ 2027 期初口径分裂

**现场**：`period::reopen_period` 只校验「期间是 CLOSED」+「后续期间没有已结账的」。年结之后 2026-12 是当年最后一个封账月
（2027 各期是 OPEN，不构成「后续已结账」），于是**反结账 2026-12 被放行**；随后往 2026-12 补记一笔：
* 报表的期初（走 `voucher_date <= 2026-12-31` 的历史累计）**变了**；
* `biz_opening_balance(2027-01, source='YEAR_END')` 快照**没变**（年结才写它）；
* 年度状态还是 `CLOSED`，从「年结」页看不出任何异常 —— 两条口径永久分裂，且只能靠改库恢复。

**修复**（`backend/src/business/erp/period.rs`，1 文件 +70 行）：
* `year_end_status_of()`：读 `biz_status_log` 里 `ACCOUNTING_YEAR` 最新一行的 `to_status`（与 `year_end::load_state_in` 同源判据，不从凭证推断 —— 空年度没有结转凭证但确实已年结）；
* `reopen_blocked_by_year_end()`：纯逻辑谓词，只有年度 `CLOSED` 才拦；`NOT_CLOSED`（反年结后）与「从没结过」都放行 —— 否则反年结之后的改账路径会被永久封死；
* `reopen_period` 在「期间状态校验」之后立刻拦：**409** + 给出唯一正路（先反年结，它会同时撤销结转凭证与下年期初台账）。
* 单测 `period::tests::p1_reopen_blocked_only_by_closed_year_end` 钉住放行/拦截两种状态。
* 真机回归：`U11` 4 条断言（409 / 文案含「已经年结」「反年结」/ 状态仍 CLOSED / 状态日志最新一条仍 CLOSED）。

### F2（P3，未修，需产品/权限口径拍板）EMPLOYEE 无 `business:attachment:upload`，而报销提交**强制**要附件

* `biz_attachment_rule`：`EXPENSE_REPORT` / `required_at=SUBMIT` / `min_count=1` / `pdf,jpg,png,ofd`；
* 权限矩阵（V0258）：`FINANCE_MANAGER` / `FINANCE_DIRECTOR` / `GENERAL_MANAGER` / `PURCHASE_MANAGER` / `WAREHOUSE_MANAGER` 有
  `business:attachment:upload`，**`EMPLOYEE` 与 `SALES_CLERK` 没有**；
* 实测：`cls01_clerk`（EMPLOYEE）建单成功 → 提交被附件闸 400 挡 → 上传附件 403 → **员工无法自助完成一张报销**，
  必须财务代传（本演练即由财务经理代传后才提交成功）。
* 为什么没顺手改：`attachment::handler::upload` 只校验「单据存在」，**没有归属校验**，把 upload 码给 EMPLOYEE
  等于允许任何员工往任何单据（他人报销单 / 合同 / 收付款单）挂附件。正确改法两步一起做：
  ① 上传时按 `doc_type` 校验当前用户对单据的可见性/归属（复用各模块详情口径）；② 再给 EMPLOYEE 授权。
  建议单开一张卡（权限矩阵 + 归属校验），不塞进本次演练。

### F3（P4，观察项）2026-12 科目余额表的「本期发生额」包含结转凭证

`trial_balance` 的 `period_debit/period_credit` 不按凭证类型过滤，年结后 12 月本期发生额多出 60 000（结转凭证的 8 行）。
科目余额表口径下这是**对的**（它确实是一张 12 月的凭证），但和利润表「本期发生额排除 `YEAR_END`」不同口径，
对账时容易被当成不平。已在 README 记录，不改代码。

### F4（P4，观察项）2026-12 空月结账也会跑期末外币重估联动

本演练无外币科目，无影响；仅记录结账事务里 `fx_revaluation` 的挂点（`period.rs::close_period` 第 ⑤ 步）对有外币余额的库会产生 12 月凭证。
