## 三、与卡面的三处**有意偏离**（先看这里，别当成 bug）

1. **模板是 28 列，不是 27 列** —— 卡面 A..AA 的 27 列**一列未动**，第 28 列（末尾）
   追加了「工号」。理由：卡面「关键规则」要求「工号留空 ⇒ 自动取号」，而 27 列里没有工号列，
   「若填」永远不成立；且 `employee_no.rs` 明确支持企业既有工号（`E2003` 这类）对接，
   批量建档时强制换成 `EMP-xxxx` 会让历史单据对不上人。卡面「注意事项」本身允许
   「追加新列到末尾」，于是补在最后。
   （不填 = 系统取号；填了 = 原样保留，撞号会在预检里点名行号。）
2. **枚举值比卡面多几个**（都是库里合法的码）：
   证件类型给了「身份证 / 护照 / 港澳台通行证 / 外国护照」（库只有 4 个码，卡面的「其他」被
   拆成后两个）；用工类型给了 6 种（多「兼职 / 派遣」，否则这两类员工永远进不了系统）。
3. **「已跳过 N 行（重复）」由前端算**：`N = 预检通过数 − 确认回执的 imported_rows`。
   后端 `persist` 只把真正写入的行计入返回值（`ON CONFLICT DO NOTHING` 跳过的不算），
   所以这个差值是唯一可信来源；前端不按身份证自行去重（拿不到跨批次历史）。

## 四、本卡顺带修掉的两处框架级缺口（影响所有导入定义）

1. **模板的列文本格式 / 表头批注 / 示例行灰色斜体**：`nik-utils` 的 `XlsxSheet` 原来只支持
   「表头加粗 + 冻结 + 数据验证」，现在加了三个**向后兼容**的可选项
   （`with_text_columns` / `with_header_comments` / `with_sample_first_row`），
   `impexp::template` 对**所有**定义的模板都启用。理由：Excel 通用格式会把 18 位身份证 /
   19 位银行账号当数值（15 位有效位，后几位静默丢失），用户填完就回不去了。
2. **「错误行」xlsx 带上原始数据**：原来只有「行号 / 列名 / 原因」，用户拿到它还得回原文件
   按行号找那一行（而原文件往往已改过）。现在 `GET /impexp/import/{id}/errors/file`
   会读回落盘的原文件，输出「行号 + 原始 28 列 + 错误列 + 错误原因」，用户改完可直接重传
   （多出的三列只触发 E-IMP-04 警告，不阻断导入）。读不到原文件时自动退回旧口径。
