# DC-03 收货过账复核来源采购单 — 真机与回归证据

- 卡：`t_2624e527`【ERP-P0】收货过账复核来源采购单状态（已取消的采购单仍能入库并生成应付）
- 来源：ARCH-3 审计 §5 **DC-03**（P0）/ §6 R-P0-3
- 基线：`81ada35`（DC-09 计量单位止血）
- 结论：**过账路径已补上来源采购单两道复核**——① 状态（与建单同一判据，出口 `409 + 66031`）；
  ② 本次过账数量 ≤ 可用待收量（口径复用 `POSTED_RECEIVED_SQL`，出口 `409 + 66032`）。
  两条复核都在**同一事务内、扣减库存之前**，并先 `FOR UPDATE` 锁采购单头 ⇒ 并发取消 / 并发过账都串行化。
  巡检侧补了 **D6**（`erp_invariants.py`）与 **DI-16**（`snapshot-drift`）。

## 1. 病灶（审计原文已复核）

| 环节 | 代码位置 | 当时做了什么 |
|---|---|---|
| 收货单**建单 / 改单** | `stockin_handler.rs::require_purchase_order`（原 :476） | 校验来源采购单「存在 + 可收 + 仓库一致」，不可收 → 400 |
| 收货单**过账** | `stockin_handler.rs::purchase_item_snapshot`（原 :695） | **只取 `qty` / `received_qty` 两个数量**，不看状态 |

于是这条时序成立：建单时采购单 `SUBMITTED` → 有人在采购页把采购单**取消 / 关闭** → 收货单过账照样跑完
→ 三本账（成本账 / 库位账 / 流水）+ 应付单 + 进项凭证全部生成，而采购单状态被 `sync_purchase_status`
静默跳过（不可收的状态不在它的白名单里）。

> 另一条同类漏洞（本卡一并补掉）：**两张收货单双开**——采购单 100、两张草稿各收 60，
> 建单时两张都按「未收 100」通过（那时还没有已过账收货），先后过账就重复入库 120。
> 旧代码只有 `add_received_qty` 的条件更新兜底，报的是 400 且发生在库存已经加完之后（靠整笔回滚）。

### 为什么用 `FOR UPDATE` 而不是 `FOR SHARE`

两种锁都能挡住「取消采购单」的普通 `UPDATE status`。选 `FOR UPDATE` 是因为**两张收货单收同一张采购单**
也要互斥：`FOR SHARE` 彼此相容，两个过账事务会同时通过待收额度复核，只能靠 `add_received_qty`
兜底（报 400 而不是带待收量的 409）。

## 3. 报文（逐字）

```text
# 66031 来源采购单已不可收（409）
来源采购单 PO-xxx 当前是「已取消」（CANCELLED），不能过账入库：它在「建单」与「过账」之间被取消 / 关闭了。
只有已提交（SUBMITTED）/ 已审批（APPROVED）/ 部分收货（PARTIAL_RECEIVED）的采购单能收。
本单未过账：库存三本账、应付单、进项凭证一条都没有生成。请核对采购单现状 ——
本单仍是草稿（DRAFT）的改单或作废后重开，处于过账审批中（PENDING_POST）的先撤回再处理

# 66032 本次过账超过待收量（409）
第 1 行本次过账 60 件，但来源采购单 PO-xxx 第 1 行只剩 40 件待收（订单 100、已过账收货 60）：
另一张收货单可能刚过账收走了。本单未过账（库存三本账 / 应付 / 凭证都没动），
请把这一行改到 40 件以内，或先核对已过账的收货单
```

- 采购单号 / 状态标签 / 状态码 / 可用待收量 / 订单量 / 已收量 **全部来自库里的当前值**；
- 「本单未过账」是给财务看的：被拒时三本账、应付、凭证一条都没写（整笔回滚，含 `biz_status_log`）。

> **卡面单测 B 的时序与可达性**（实测差异，已写进用例注释）：
> 卡面写「建 A（60）→ 建 B（60，采购单只剩 40）→ 过账 B」。但 A 过账后采购端只剩 40，
> B 按 60 建单会被 D4 建单闸**当场 400**，B 根本建不出来。真正可达的双开是
> 「先建两张（各自都按未收 100 通过）→ 再先后过账」，用例钉的就是这条。

## 9. 已知取舍与后续

| 项 | 说明 |
|---|---|
| **锁顺序**（已知，非本卡范围） | 过账路径 = 收货单头 → 采购单 → 库存行；作废路径（`stockin_cancel`）= 收货单头 → 库存行 → 采购单。两条路径同时处理**同一物料同一仓库**时会构成环，PG 在 `deadlock_timeout` 内检测并中止其中一笔（40P01），被中止的整笔回滚、可重试，不会留半笔账。彻底消除需统一两边加锁顺序 → **已开卡**（P2） |
| 无源单据 | `source_order_id IS NULL`（期初 / 复制 / 其他）没有采购单可复核，两道闸都不适用（与 A4 的 `is_sourceless` 口径一致） |
| 存量 | 过账闸只挡**新**过账；已过账的存量靠 D6 / DI-16 盯，本卡不自动改历史数据 |
| 审批路径 | `PENDING_POST` 审批通过后的过账走**同一个** `post_in_tx`，因此同样受两道闸约束；审批期间采购单被取消 ⇒ 审批通过时会 409，单据停在 `PENDING_POST`（报文提示先撤回） |
