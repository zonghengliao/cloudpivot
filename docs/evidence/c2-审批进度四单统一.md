## 六、决策与取舍

1. **不新抽 composable**：`shared/approval-progress.ts` 已经是四单共用的装载器（本卡把收货 / 应付的内联
   `map(node)` 删掉，统一走它），再抽一层 `views/business/flow/composables/useApprovalProgress.ts` 只多一层壳；
   卡面亦允许「风险大于收益就说明不抽」。
2. **调拨单保留一行「提交人 · 提交时间 · 单号」**：自绘时间线原来有「提交」这一步，而 `FlowProgress` 只画
   引擎节点（`nodes[]` 里没有发起人 / 发起时间）。为了不默默丢信息，补一行文字，口径直接取
   `buildApprovalSteps(instance, [])[0]`（与老时间线、审批详情页同一套文案）；「完成 / 驳回」这类终态由 END
   节点的状态文案覆盖，不再单独画一行。
3. **给应付 / 凭证补 `.section-title` 样式**：两页模板早就在用这个 class 但**没有对应样式**（标题挤在上一个块
   末行），与其它单据看起来不一样；按采购 / 收货的同一组值（`margin:16px 0 8px; font-size:13px; 600`）补齐。
4. **`FlowProgress.vue` 一个字未改**（四个页面共用，改成按单据分支风险大）；新单测钉住它的 props 契约
   （`nodes` 必填、`tasks?` 可选）与「组件里不出现单据名」。
