## 3. 表结构与口径

### 3.1 `biz_stock_out`（单头）

```text
id / out_no(OUT-yyyyMMdd-000001) / out_type(ISSUE|SCRAP|LOSS|OTHER) / warehouse_id / out_date
status(DRAFT|PENDING_POST|POSTED|CANCELLED) / total_qty / total_amount / voucher_id
reason / remark / posted_at,posted_by / cancelled_at,cancelled_by,cancel_reason
created_at,updated_at,create_by,update_by,deleted_at
```

* `total_amount` 是**成本结转金额**（= Σ 明细 `amount`），草稿为 0，过账时按账上真实差额写入；
* `ck_biz_so_cancel`：作废必须有 `cancel_reason`（红字凭证摘要与审计都要）；
* 单号唯一是**部分索引** `WHERE deleted_at IS NULL`（软删后可复用，与 `uk_biz_si_no` 同口径）。

### 3.2 `biz_stock_out_item`（明细）

```text
id / stock_out_id(硬外键, ON DELETE CASCADE) / line_no / material_id / unit_id(Q 唯一来源)
qty(>0) / unit_cost(过账时的移动加权单价快照) / amount(过账时账上真实扣减金额)
location_id(→ biz_inventory_location.id，NULL=未分配库位桶) / lot_no / remark
```

* **`location_id` 的口径与 `biz_stock_in_item.location_id` 完全一致**：指向 `biz_inventory_location.id`
  （库位库存行），不是 `biz_location.id`（见 `stockin_write.rs:548-566` 与 V0139 文件头 ①）。
  脚本与单测都钉住了这条：传 `biz_location.id` 会 400 并说明「不是 biz_location.id」。
* **单价 / 金额不让客户端传**：出库成本必须由过账时 `biz_inventory` 的 `before/after` 决定。

### 3.3 状态机（`state_machine::STOCK_OUT_EDGES`，6 条边）

```text
DRAFT ──────────→ PENDING_POST ──→ POSTED ──→ CANCELLED
  │                    │                        ▲
  └────→ POSTED ───────┴──→ DRAFT（撤回）        │
  └──────────→ CANCELLED ──────────────────────┘
```

* `POSTED → CANCELLED` 是**唯一需要 reason 的边**（`STOCK_OUT_REASON_EDGES`）；
* 故意**没有** `PENDING_POST → CANCELLED`：待过账从未动账，作废它等于「撤回 + 作废」两步；
* 入账态 `STOCK_OUT_LOCKED = [POSTED, PENDING_POST]`（入账 / 待过账都不可再改）。

## 4. 过账事务（一个事务，任一步失败整笔回滚）

```text
① 锁单头（FOR UPDATE，并发重复过账在这里串行化；起始态 ∈ {DRAFT, PENDING_POST}）
①b 期间闸：out_date 所属会计期间已 CLOSED → 400（错在入口，不留半张凭证）
①c 制单 ≠ 过账（erp.separation_of_duties.post 开关，默认关闭，与收货同款）
② 状态机唯一入口（边表 + biz_status_log）→ CAS 改状态
③ 逐行（按 material_id / location_id NULLS FIRST / line_no 排序 = 全局锁序）：
     lock_bucket（FOR UPDATE 成本账行）
     ├─ 无行 → 409 + 66034（报「可用 0」）
     ├─ allow_negative = 0 且 bucket.qty < qty → 409 + 66034（点名物料与可用量）
     deduct_cost：qty −、amount −、avg_cost 按剩余金额重算（整桶取完 amount 归 0）
     lock_location_row（库位账行）→ 同一套负库存闸 → deduct_location_qty：qty −
     write_txn：txn_type=OUT（qty 恒正、amount ≥ 0），biz_type = ISSUE_OUT/SCRAP_OUT/LOSS_OUT/OTHER_OUT
     set_item_cost：回写 unit_cost（均价快照）/ amount（**账上真实差额**）
④ 单头 total_amount
⑤ create_for_stock_out：借 6401（领用/其他）或 1901（报废/盘亏）/ 贷 1405，金额 = 真实差额；
   差额 ≤ 0（零成本存量）→ WARN 跳过凭证（不报错）；成功后回写 voucher_id
```

**金额口径（硬红线）**：明细 / 单头 / 凭证三处金额全部取 `before.amount − after.amount` 的
**账上真实差额**，不用 `qty × avg_cost` 重算 —— 多桶与 4 位舍入下两者不等，
用重算值贷 1405 会让巡检 B2（库存金额 = 1405 余额）报 0.00x 的 BLOCKER。

**为什么三本账必须同事务**：只减成本账不减库位账 → B1 立刻红；只减账不写流水 → B4 立刻红。
这是 P6「收货同时写两本账」的同一条铁律的反向版。

## 5. 作废（`POSTED → CANCELLED`）

```text
① 锁单头 → 状态机留痕（reason 必填）+ CAS
② 流水完整性闸：明细行数 ≠ 过账 OUT 流水行数 → 409 + 66035（**绝不按现价估算**）
③ 逐行（同一锁序）：lock_bucket 拿 before → restore_cost（qty + / amount + item.amount / 重算均价）
   → restore_location_qty → 回读 after → write_cancel_txn（txn_type=IN + STOCK_OUT_CANCEL）
④ 红字凭证：voucher::reverse_by_source(SOURCE_STOCK_OUT, …) → 原凭证 reversed_by 指向红字，
   单据 voucher_id 改指红字（详情页一跳看到冲销）
```

草稿 / 待过账作废：只改状态 + 写 `cancel_reason`，三本账一分不动。

## 6. 巡检增强（`erp_invariants.py`）

| 编号 | 内容 | 级别 | 为什么需要 |
|---|---|---|---|
| **B5** | 已过账（`total_amount > 0`）的出库单必须有蓝字凭证，且 `total_debit = total_amount` | BLOCKER | 没凭证 = 成本没进 6401/1901、1405 没减 → 存货虚增，而 B1/B2/B4 仍然「平」 |
| B5b | 已过账但金额 = 0 的出库单（零成本存量）逐张列出 | INFO | 按设计跳过凭证，财务按需补账；列出来才看得见 |
| **B6** | 出库累计 ≤ 入库累计（含期初），`allow_negative = 1` 的仓排除 | BLOCKER | B4 的负向版本：货出了但入库/期初没记 |

套件不能因为一张新表没上线就整组炸掉。

请求体（建单 / 改单）：

```json
{
  "out_type": "ISSUE",
  "warehouse_id": "…",
  "out_date": "2026-11-02",
  "reason": "车间领用",
  "remark": "…",
  "items": [{ "material_id": "…", "qty": "30", "location_id": null, "lot_no": null, "remark": null }]
}
```

状态流转：`{"status": "POSTED"}` / `{"status": "PENDING_POST"}` / `{"status": "DRAFT"}` /
`{"status": "CANCELLED", "reason": "领错料，退回"}`（作废必填 reason）。

错误码：

| 码 | HTTP | 场景 |
|---|---|---|
| `66034` | 409 | 负库存拦截（报文点名物料编码/名称 + 该桶可用量 + 仓库；不允许负库存的仓） |
| `66035` | 409 | 作废时过账流水缺行（拒绝按现价估算） |
| `66002` | 400 | 仓库 / 物料 / 库位账行不存在 |
| `10001` | 400 | 数量 ≤ 0、明细为空/超 200 行、类型非法、报废·盘亏未写原因、一物一码物料 |

## 9. 边界（刻意没做的事，与卡面的差异）

1. **不接审批流引擎**。出库没有种子流程，本卡也不新增 `biz_type` / 不种流程：
   `PENDING_POST` 是**真的可用状态**（提交待过账 → 他人过账），配合
   `erp.separation_of_duties.post` 开关实现「制单 ≠ 过账」。**没有静默降级** ——
   本模块不声明任何审批流程，也就不存在「流程没配就直接生效」的语义（DC-01 的反面）。
   后续若要接审批，需要：种 `stock_out_post` 流程 + 写 bridge 回调（照 `stockin_bridge`）。
2. **一物一码物料禁止走出库单**（400，报文指路 `PATCH /business/erp/serial/{id}/status`）：
   序列号件数与账面数量必须相等（不变式②），那条件数只由 `serial_handler` 维护，
   走本单会把它冲成负数。
3. **前端页面未做**：`views/business/erp/stock-out/` 与 `api/business/erp/stock-out.ts` 留作后续卡
   （本卡的验收项全在后端：迁移 / 事务 / 巡检 / 单测 / 隔离库全链）。
   接口契约见 §7，`StockOutDetailRes` 直接带 `next_statuses` 与 `legal_edges`，前端不用再写一份状态机。
4. **领用不按部门/成本中心归集**：`biz_stock_out` 没有 `dept_id`（1405/6401 的辅助核算也没开部门维度），
   领用去向只落在 `reason` 文本。要做「部门成本归集」需要新列 + 报表口径，属另一张卡。
5. **期初存量不补**：零成本（`qty>0/avg_cost=0`）的历史库存出库时金额差为 0 → 按设计跳过凭证（WARN + B5b INFO），
   不自动补账（与 `serial_handler` 的 ADR 口径一致）。
6. **allow_negative 仓库允许负数量**：数量可以转负，但金额只减到 0（差额按实际减掉的部分结转），
   巡检 C1/B6 对这类仓**豁免**（那是仓库自己的策略）。
