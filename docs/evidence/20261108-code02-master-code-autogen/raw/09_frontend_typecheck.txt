CODE-02 前端侧检查（本卡**没有改前端**，只是确认没被后端 DTO 变化带崩）

## 命令
cd /opt/cloudpivot/frontend && NODE_OPTIONS=--max-old-space-size=6144 pnpm typecheck
（= vue-tsc --noEmit；退出码 0）

## 结果
- 第一次用默认 node 堆跑：`FATAL ERROR: Ineffective mark-compacts near heap limit` → 退出码 134。
  这是**前端包体变大后的默认堆不够**（共享机上同时还有别的卡在编 rust，内存吃紧），不是本卡改动引起：
  本卡 5 个改动文件全在 backend/，frontend/ 一个字节没动。
- 把堆抬到 6GB 后重跑：**退出码 0**（vue-tsc 成功时不打输出）。

## `pnpm build` 为什么没在本卡跑
`frontend/dist` 是共享工作区里别人在用的上线产物（同一个 /opt/cloudpivot 工作区、多 worker 直接提交 main），
本卡不碰前端却去覆盖 dist 会干扰前端卡的发布节奏。前端表单的「生成编码」按钮 + 去掉 `supplier_code` 必填校验
是 CODE-05 的卡，由那张卡负责 `pnpm typecheck && pnpm build`。
