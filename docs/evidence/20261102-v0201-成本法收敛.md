- 改动范围：`dto::COSTING_METHODS` 收敛 + 专门 400 文案；迁移 `V0201`（回填 + 收紧 `ck_biz_material_costing`）；前端主数据「成本法」下拉单值 + 灰字说明

## 0. 一句话结论

`costing_method` 的消费方 **0 处**（`stockin_write.rs` / `transfer_settle.rs` / `serial_model.rs` 全文不读它，成本一律 upsert `avg_cost`），
所以以前选 FIFO / STANDARD 会**静默按移动加权算**。本卡把值域收敛到唯一实现（DTO 400 + DB CHECK + 前端单值下拉），
并核对存量 **0 行需要回填**。「选了不会算错」由接口与库两层同时保证。

```sql
SELECT material_code, material_name, costing_method

```

**结论：三库命中 0 行 ⇒ 无需业务侧确认任何「改口径」清单，迁移里的回填在现网是 no-op。**
（迁移仍保留回填分支：别的环境若命中，S1 会先逐条播报 `material_code=旧值` 到迁移日志留痕，再 UPDATE。）

另：`biz_material` 上的 CHECK 实测存在（`\d biz_material` → `pg_constraint`）：

```
ck_biz_material_costing | CHECK (costing_method IN ('MOVING_AVG','FIFO','STANDARD'))   ← V0137 原样
```
`biz_material` **无外键、无唯一约束**（只有 PK），故 down 的可逆性探针用「插-删」而非靠 FK 拦。

```sql

-- 代码回滚：revert 本卡 commit（dto 常量 + 前端常量成对回退，别只回退一半）
```

**可逆性说明**：down 只把 `ck_biz_material_costing` 放宽回三值域，**不会**把被 up 回填过的行改回 FIFO/STANDARD
（原值未随行保存；来源只有 up 的 S1 迁移日志）。本次三库命中 0 行 ⇒ 现网回滚**零数据损失**。
完整 FIFO 需要「批次成本层」（`biz_material_batch` + 出库按批次核销），属专项，不在本卡范围。
