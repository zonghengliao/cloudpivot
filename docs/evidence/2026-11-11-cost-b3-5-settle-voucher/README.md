## 1. 本卡交付了什么

结算事务（B3-6）里的**凭证步骤**，无 HTTP 入口（设计 §5.2 没有「发凭证」接口，凭证是结算的内部步骤）：

| 步骤 | 函数 | 分录 | 条件 |
|---|---|---|---|
| ④-a 人工计提 | `post_labor_voucher` | 借 `4001.02`（按车间，`aux_dept_id`）/ 贷 `2211.01` | `labor_source='PAYROLL'` 或金额 0 ⇒ 不出（§4.7.2 末段） |
| ④-b 手工台账 | `post_ledger_voucher` | 借 `4101.xx` / 贷 `credit_account_code` | 无台账行 ⇒ 不出（§4.7.3 第二段 / §4.8 ④「按需」） |
| ④-c 制造费用结转 | `post_overhead_voucher` | 借 `4001.03`（按车间+科目，`aux_dept_id`）/ 贷 `4101.xx`（按科目清零） | 合计 0 ⇒ 不出 |
| ④-d 完工结转 | `post_finish_voucher` | 借 `1405`（按成本对象，`aux_material_id`+`aux_warehouse_id`）/ 贷 `4001.01`·`.02`·`.03`（按要素三行）；随后回写 `biz_stock_in.voucher_id` | **必备**（`ck_biz_cost_period_settle`），金额 0 ⇒ 409 + `66075` |

一次调齐：`post_all(ex, ctx) -> SettledVouchers`（含三个 voucher_id + 合计 + 要素拆分，供 B3-6 回写与事务内断言）。
全部凭证经 **`voucher::post_voucher`** 唯一收口（≥2 行 / 借贷平衡 / 只许末级科目 / 期间未结账四道闸都在那里）。
`voucher_ids_of(period_id)` 供 B3-7 红冲按批次反查。

## 4. 与设计原文的偏差（详见模块头注释与卡内说明）

1. **制造费用结转的借方包含「直接行」**（挂成本对象的手工台账）。§4.7.3 原文写 `Σ 池金额`，但直接行的 4101 借方同样要清 —— 只清池会让 4101 期末余额 ≠ 0（C-COST-1）且 Σ`4001.03`借 ≠ Σ`item.oh_cur`（C-COST-3、本模块 `66076` 直接拦）。按设计写明的**目的**（「把 4101 清零，让制造费用全部进产品成本」）实现。用例 6 是这条的正反证据。
2. **多一张「手工费用台账」凭证**（`Option<Uuid>`）：手工台账是唯一没有上游凭证的费用来源（折旧/报销在上游已借 4101），不先记进 4101，④-c 的贷方 4101 就没有对应借方。§4.7.3 第二段 + §4.8 ④「第 4 张，按需」已点名这张，不是新设计。
3. **完工结转的要素拆分**：计算单只存 `finished_cost` 与三个 `unit_*`，没有「完工材料/人工/费用」三列，所以贷方按 `round(qty × unit_*, 4)` 拆，尾差按 **制造费用 → 材料 → 人工** 吸收（与 B2-11「期初在制差额落制造费用」同口径）。三个要素都吸收不了（要出负数行）⇒ 409 + `66076`，绝不硬造负贷方。
4. **新增两个错误码**：`66075`（无完工金额不能出完工结转凭证 / 不能结算）、`66076`（凭证金额与计算单不一致，三处断言共用）。
