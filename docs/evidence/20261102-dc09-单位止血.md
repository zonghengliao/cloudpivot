# DC-09 计量单位止血（方案 B）— 真机与回归证据

- 卡：`t_d594ede3`【ERP-P0】计量单位止血：单据禁用非基本单位（rate 配了不生效）
- 来源：ARCH-3 审计 §5 DC-09 / §6 R-P0-4
- 基线：`cec9d99`（成本法收敛）
- 结论：**单据侧闸门已收紧**——采购 / 收货 / 调拨三处建单、改单，明细的单位必须是
  `biz_unit.is_base = 1`，否则 `400 + 66030` 并给出折算建议。存量三库命中 **0 行**。

## 1. 病灶（审计原文已复核）

`biz_unit` 有 `is_base` / `base_unit_id` / `rate`（主数据 CRUD 可填），但**单据链路 0 处读取**：
明细入参根本没有 `unit_id` 字段，明细的 `unit_id` 由 `biz_material.unit_id` 带出，
库存三本账（`biz_inventory` / `biz_inventory_location` / `biz_inventory_txn`）直接加减 `qty`。
按「箱」下单 5 箱 → 库里 `qty = 5`，账上 5 个而不是 60 个。

| 单据 | 明细表 | 有 `unit_id` 列 | 单位来源 |
|---|---|---|---|
| 采购订单 | `biz_purchase_order_item` | 有 | `biz_material.unit_id` |
| 收货入库 | `biz_stock_in_item` | 有 | `biz_material.unit_id` |
| 库存调拨 | `biz_stock_transfer_item` | **没有** | 无（数量直接进两本账） |

> 卡面写「调拨明细也存 `unit_id`」与实测不符：`\d biz_stock_transfer_item` 只有
> `material_id / qty / shipped_qty / received_qty / unit_cost …`，没有 `unit_id`。
> 判据因此统一落在**物料的基础单位**上（三处同一判据、同一文案）。

### 报文（逐字）

```text
items[0] 物料 P2A2-M3-BOX：单位「箱」不是基本单位：本版本不支持多单位换算，
请按基本单位录入（1 箱 = 12 个 → 录 60）
```

- `items[i]` = 请求体里的行下标（一单多行时用户知道改哪一行）；
- `1 箱 = 12 个` 的 12 是 `biz_unit.rate`、`个` 是折算基准单位名（`base_unit_id` 关联出来）；
- `→ 录 60` = 本行 `qty × rate`（4 位四舍五入），用户照抄就能过；
- HTTP `400`，`code = 66030`（新增专用码，不复用 `66006 筛选参数`：前端要把它翻成
  「按基本单位录入」的行级引导）。

## 6. 已知边界（本卡**刻意**不做）

1. **不做换算**：不新增 `qty_base` 列、不改三本账 —— 完整方案 A 属专项（动 4 张明细表 +
   三本账 + 巡检 B4），必须在克隆库跑完 B1/B2/B4 全绿再上。
2. **不动主数据**：`biz_material.unit_id` 仍可指向折算单位（本卡只在物料弹窗加灰字提示）。
   真要做硬约束是**另一张卡**（会牵连既有物料语义与主数据校验）。
3. **不改存量数据**：存量命中 0 行，无数据修正。
4. **复制收货单**（`copy_stock_in`）沿用原单的 `unit_id` 快照、不过闸 —— 它不产生新口径，
   且存量 0 命中；将来若出现非基本单位的老单，复制出来的单同样会被后续过账链路按老口径处理，
   属方案 A 的范围。
5. **过账 / 结算不复检单位**：闸门在「建单 / 改单」，`PATCH …/status=POSTED` 与调拨
   「发货 / 收货」不再查 `is_base`。理论上「升级前建的折算单位草稿」仍能过账，
   但三个库的存量排查 **0 命中**，现网不存在这类草稿。真要堵死，应在
   `post_stock_in` / 调拨 `settle` 里按**明细快照的 `unit_id`** 再查一次 `is_base`
   （与 A4 的 `guard_posting_supplier` 同一思路：绕过接口的 UPDATE 建单期挡不住），
   这是独立的一张卡，本卡不动。
