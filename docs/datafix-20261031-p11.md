# P11 数据修复留痕：任务取消后审批待办成孤儿（2026-10-31）

> 老板原话（2026-10-31）：
> 「工作任务里，有一个任务在超管那已经取消了，但是在 henry.liao 用户里还是等待审批，
> 并且不能做任何操作。任务名：TSK-202610-000149 E6A-UI验收-子任务A」
>
> 根因：`task::handler::change_status` 把任务推到 `CANCELLED` 时只级联取消了**子孙任务**，
> 没有撤它的**审批实例与待办**（「铁律① 正向必配反向」缺反向）。删除任务那条路径
> （`flow::task_bridge::cancel_on_task_deleted` → `flow::model::cancel_pending_of_biz`）
> 早就修好了，取消任务这条漏了。

## 1. 代码修复（同事务级联撤审批）

| 文件 | 改动 |
|------|------|

| 编号 | 级别 | 判据 |

## 3. 修复脚本

`scripts/datafix/p11/`

| 文件 | 作用 |
|------|------|
| `10_cancel_orphan_tasks.up.sql` | 只把「`ft.status='PENDING'` ∧ 所属实例已终态 ∧ 实例未软删」的待办改成 `CANCELLED` + `completed_at=now()` + 文案；末尾 DO 块自检（还有脏行就 `RAISE EXCEPTION`） |
| `10_cancel_orphan_tasks.down.sql` | 只回滚「`comment` 正好是本脚本文案」的行（原本有 comment 的不动，用备份恢复），`completed_at` 清回 NULL 以满足 `ck_biz_flow_task_done` |
| `apply.sh` | 备份（两张表全量 CSV + MANIFEST）→ dry-run/apply → 幂等复核 → 审计事实计数 → 演练库 up/down/up 往返 |

红线执行情况：

- **只动组合**「实例已终态 + 待办 PENDING」，不动任何其它行；不动 `APPROVED/REJECTED/SKIPPED/TRANSFERRED`（审计事实）。
- `biz_flow_task` 没有 `updated_at` 列，`ck_biz_flow_task_done` 要求 `(status='PENDING') = (completed_at IS NULL)` → 状态与 `completed_at` 同写。
- 幂等：第二遍 `UPDATE 0`（见下）。

老板报的那条：

```
task_no              | TSK-202610-000149
任务状态              | DONE（**已软删** deleted_at=2026-10-30 10:24:40）
审批实例              | FLW-20261030-1BAE2858  CANCELLED
```

⚠️ **口径差异要写清楚**：卡面验收①说「超管 → 工作任务 → TSK-202610-000149 期望：状态已取消」，
而库里这条是 **`DONE` + 已软删**（`sys_change_log` 里只有 `TODO→DOING`、`DOING→REVIEW` 两条，
`DONE` 是审批通过由 `flow::task_bridge::settle` 写的，删除动作发生在 10:24:40）。
也就是说：老板当时看到的「已取消」不是这条任务的 `biz_task.status`，
而是**审批侧已经结束**（实例 CANCELLED）却还挂着待办这件事。本卡不修改 `biz_task` 任何字段
（数据修复只 `UPDATE biz_flow_task`），所以任务侧状态**保持原样**（`DONE` + 软删），
`H2` 对 `DONE` 同样成立（实例已 `CANCELLED`，不是 `PENDING`）。
