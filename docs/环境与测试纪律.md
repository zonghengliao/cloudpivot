## 一、三台机器各干什么

| 机器 | IP | 角色 | 允许做什么 | **禁止做什么** |
|---|---|---|---|---|
| **99** | 本机 | **Hermes Agent 主机** | 跑 kanban dispatcher / worker、写代码、git、推送 | **不跑测试、不建测试库、不起测试实例** |
| **145** | 172.18.10.145 | **测试机** | 编译、自动部署、单元测试、E2E 演练、建演练库 | 不跑生产流量 |
| **144** | 172.18.10.144 | **生产机** | 只跑正式服务 + 冒烟验证 | 不跑测试、不建演练库 |

---

## 二、为什么 99 不跑测试

**99 是 Hermes Agent 的宿主，不是通用开发机。**

```
① 跑着 kanban dispatcher（每 3 分钟一轮调度）
② 跑着多个 worker（每个 300MB+）
③ 内存 15G，常驻 3–5G（agent + worker + gateway）
④ 磁盘上已经积累了 60+ 个废弃演练库（见第四节）
```

**在 99 上跑测试的代价**：

| 问题 | 表现 |
|---|---|
| **污染 agent 环境** | 测试实例占端口、占内存，worker 变慢甚至被 OOM kill |
| **库越积越多** | 99 上已有 60+ 个 `*_e2e` / `*_drill` 库，从未清理 |
| **干扰构建缓存** | `cargo test` 与 worker 的 `cargo build` 抢 target 锁 |
| **角色混乱** | 99 的职责是「指挥」，不是「干活」 |

## 三、测试的标准做法（全部在 145）

### 单元测试

```bash
ssh root@172.18.10.145
cd /opt/cloudpivot
./scripts/ops/run_tests.sh backend          # 后端（单 job + 关 debuginfo）
./scripts/ops/run_tests.sh frontend         # 前端（node:test）
```

### E2E 演练

```bash
ssh root@172.18.10.145
cd /opt/cloudpivot
export NIK_ADMIN_PASSWORD='<演练口令>'      # 空库首启的 admin 种子
bash scripts/verify/cost_e2e.sh             # 自建演练库 + 起隔离实例 + 跑 + 清场
```

**注意**：脚本会建 `cost_e2e_drill` 库、起 `:18140` 实例，跑完自动清场。

### 生产冒烟（144）

```bash
curl http://172.18.10.144/health
curl -X POST http://172.18.10.144/api/system/auth/login ...
```

**只做只读验证，不造数据、不跑演练。**
