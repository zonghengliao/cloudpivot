## 3. 口径决策（执行卡必须逐条遵守）

**D1（闸② 判定面 = 生产面）** 闸② 只判定「会进生产编译的代码」：
1. 由父模块以 `#[cfg(test)]` 声明的模块文件，整文件跳过；
2. 文件内 `#[cfg(test)] mod xxx { … }` 的区域跳过（含 `#[cfg(all(test, …))]`）。
   `#[cfg(test)] #[path = "…"] mod tests;` 这种挂载必须解析（仓内有 6 个测试文件靠它）；
3. 跳过**必须可审计**：脚本每次运行打印「跳过 N 个测试面文件、M 个测试区」，并保留现有
   扫描范围硬断言（`business/task`、`business`、`system`、`support`、`shared` 目录存在且非空）。

**D2（为什么可以跳过）** 这些模块只进 test profile，不进生产二进制（`business/erp/mod.rs:144-149`、
`business/flow/mod.rs:65,82`、`system/mod.rs:33-35`、`business/task/model.rs:97,133-141` 逐行可查）；
测试夹具**必须**跨部门全量查库（建 `p3b_%` 用户、`DELETE … WHERE username LIKE`、`count(*)` 断言），
注入 scope 只会让夹具自身失效。B5 之后「每个新测试文件都要补一行 SCOPE-EXEMPT」就是 35 个回潮的直接机制，
用标记法继续补是维护 treadmill，故改为按编译面判定。

**D3（生产面不放宽）** 生产面仍然「`scope::` 或 `// SCOPE-EXEMPT: <理由>`」，且：
1. 豁免标记写在**豁免函数正上方**（函数级），理由必须回答「注入了会怎样错」+「权限在哪校验（file:line）」；
2. **禁止**用一条文件级豁免掩盖「产出用户可见行集」的查询：判据是「该查询的调用方是否会把这些行
   直接展示给用户」；是 → 必须接 `scope::filter_for`/`scope::paginate`，不许豁免；
3. 第 7/8 项没有现成结论的，执行卡必须给出调用链证据（handler 行号 + 权限校验位置）后才能豁免。

**D4（G5 判定面 = changelog 写入入口）** 只匹配：
1. 限定名调用 `changelog::record(` / `changelog::record_in(`；
2. `business/changelog/` 模块内部对 `record`/`record_in` 的未限定调用（模块内没有 `db()`，G2 兜底）。
必须忽略：方法调用（匹配位置前一个非空字符是 `.`）、同文件本地 `fn record(` 遮蔽下的裸调用、
注释与字符串（现有 `mask()` 已覆盖）。

**D5（事务证据看类型，不看名字）** 第一个实参是标识符，且该标识符在**最近的 enclosing `fn` 形参表**里
声明为 `&Transaction` / `&mut Transaction` / `Transaction` → 合规（`cancel_flow_tasks(ex: &Transaction, …)`、
`spawn(ex: &Transaction, …)` 属此类）；形参名是 `tx` 的照旧合规。
仍然**硬拒** `db()` / `global()` / `try_db()`（第二个事务入口）。

**D6（放宽必须带负例）** 两条门禁脚本都必须自带反例（`--self-test` 或 `tests/fixtures/gates/`），
至少覆盖 5 类：① 顶层裸调 `changelog::record(db(), …)`；② `tokio::spawn` 里调 `changelog::record(&tx,…)`；
③ 事务闭包里首参传 `db()`；④ 本地 `fn record(` 遮蔽 + 裸 `record(...)`（不得误报，也不得因遮蔽而漏掉
同文件真实的 `changelog::record`）；⑤ 首参是 `&Transaction` 形参（必须判绿）。
放宽类改动若出现「负例不再报红」，视为门禁失效，不许合。

### A.3 一处口径细化（必须记录，因为它是 D5/D6 的交叉点）

D5 的类型证据**只对裸标识符首参**（`changelog::record(ex, …)`）成立；`changelog::record(&tx, …)` 这类引用写法
仍按原有事务上下文判定（在 `transaction(|tx| …)` 闭包内、或 `begin()` 显式句柄之后）。

原因：D6 负例② `tokio::spawn(async { changelog::record(&tx, …) })` 要求**报红**。如果类型证据也覆盖 `&tx`，
这个负例就会被误判绿 —— 因为 `tx` 的形参类型同样是 `&Transaction`，但它被搬进了另一个任务，可能在事务结束之后才执行。
裸标识符 `ex` 只可能是「当前函数收到的那个事务句柄」，不会跨任务移动，才是 D5 要放行的形态。
实现在 `scripts/lint/changelog_in_tx.py` 的 `IDENT_ARG_RE`（裸标识符）与 `TRANSACTION_TYPE_RE`（类型）两处。
