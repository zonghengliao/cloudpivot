# 前端二开指南

> 目标：让开发者 / AI 以最短路径新增一个页面 / 业务模块。范本优先照抄 `frontend/src/views/system/user/index.vue` + `frontend/src/api/system/user-api.ts`。
> 先看 [项目结构与设计亮点.md](./项目结构与设计亮点.md) 的目录树与「前端 `frontend/`」小节。

---

## 一、新增业务页面 / 模块的标准流程

1. **加接口封装**：在 `frontend/src/api/business/` 新建 `<模块>-api.ts`，方法直接调 `request.ts` 的 `get/post/put/patch/del`，路径**写全 `/api/...`**。
2. **加页面**：在 `frontend/src/views/business/<模块>/index.vue` 写列表页（搜索表单 + `t-table` + 分页 + 新增/编辑抽屉）。
3. **注册路由**：在 `frontend/src/router/index.ts` 的 `BasicLayout` children 里加一条，`meta: { title, permission }`，组件懒加载 `import('@/views/business/<模块>/index.vue')`。
4. **加菜单种子**：后端 `migrations/seed/` 追加菜单项（`module_code='business'`），前端路由 `path` 与菜单 `path` 对齐。
5. **类型对齐**：跨模块复用的类型放 `frontend/src/types/`；与后端 DTO 字段命名保持一致（可空文本列后端下发空串）。

## 二、接口封装（`api/request.ts` 已就绪）

`request.ts` 已封装好：注入 Bearer Token、401 自动用 refresh_token 换新并重放、统一响应体拆包（`code !== 0` 抛 `ApiError`）、`ApiResult<T>` 与 `PageData<T>` 类型。

**你的 `api/business/article-api.ts` 只写业务方法**：
```ts
import { get, post, put, del } from '@/api/request';
import type { PageData } from '@/api/request';

export interface ArticleItem {
  id: string;
  title: string;
  content: string;
  status: number;
  created_at: string;
}

// 路径必须写全 /api/...（漏前缀会命中 SPA fallback 返回 HTML → “响应体格式不符合”）
export function pageArticles(params: Record<string, unknown>) {
  return get<PageData<ArticleItem>>('/api/business/article/page', params);
}
export function createArticle(data: Partial<ArticleItem>) {
  return post<ArticleItem>('/api/business/article', data);
}
export function updateArticle(id: string, data: Partial<ArticleItem>) {
  return put<ArticleItem>(`/api/business/article/${id}`, data);
}
export function deleteArticle(id: string) {
  return del(`/api/business/article/${id}`);
}
```

## 三、列表页范本（关键结构）

参考 `views/system/user/index.vue`，核心模式：
- 搜索表单 `t-form` + 查询按钮；
- 数据表格 `t-table`（`:data` / `:columns` / `:pagination`）；
- 分页走后端：`:pagination` 绑定 `{ current, pageSize, total }`，`@page-change` 重新拉取；
- 新增/编辑用 `t-dialog` 或 `t-drawer` 承载表单。

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue';
import { pageArticles, deleteArticle } from '@/api/business/article-api';
import type { ArticleItem } from '@/api/business/article-api';

const data = ref<ArticleItem[]>([]);
const pagination = ref({ current: 1, pageSize: 20, total: 0 });
const query = ref({ keyword: '' });

async function load() {
  const res = await pageArticles({ ...query.value, page: pagination.value.current, page_size: pagination.value.pageSize });
  data.value = res.list;
  pagination.value.total = res.total;
}
onMounted(load);
</script>

<template>
  <t-table :data="data" :columns="columns" :pagination="pagination" @page-change="onPageChange">
    <template #operation="{ row }">
      <t-link theme="primary" @click="onDelete(row)">删除</t-link>
    </template>
  </t-table>
</template>
```

## 四、表单 / 抽屉注意事项（高频坑）

- **`t-drawer` 内容插槽是 `body` / 默认槽**，没有 `#content` 槽（误用 `#content` 会导致表单空白）。
- **`t-dialog` footer**：仅当 `footer` 为真才渲染；若用 `#footer` 插槽自定义，不要同时传 `:footer="false"`（冲突会抑制按钮）。
- 表单提交用 `t-form` 的 `validate()`，通过后再调接口；成功后 `MessagePlugin.success` 并刷新列表。

## 五、路由注册与权限守卫

`router/index.ts` 已在全局前置守卫里做：未登录跳 `/login`、刷新后补齐 `userStore.loadProfile()`、按 `to.meta.permission` 校验权限（无权限跳 `/result/403`）。

**新增路由**（放在 `BasicLayout` 的 `children` 内）：
```ts
{
  path: 'business/article',
  name: 'BusinessArticle',
  component: () => import('@/views/business/article/index.vue'),
  meta: { title: '文章管理', permission: 'business:article:list' },

```

## 七、主题与样式变量（`style/theme.less`）

`theme.less` 在**明暗双主题**下定义了一组品牌变量，业务代码统一引用变量而非写死色值，切换主题自动跟随：
```less

--app-brand: var(--td-brand-color-7);      // 主色
--app-brand-hover / -active / -light / -border;
--app-brand-accent: #03a3cc;               // 四色指标卡第二档（青）
```

- 首页条幅等装饰场景用 `var(--app-gradient-brand)`，明暗都能正确显示。

## 八、TDesign 高频坑（先读，避免返工）

1. **Grid 是 12 列制**：`t-col-xl-2`=一行 6 个、`-xl-3`=一行 4 个；`t-col-xs-24` **不存在**（最大 `xs-12`）。
2. **图标名**：`user-check` → `user-checked`、`speed` → `rocket`（TDesign 无这两个名，写了渲染空白）。
3. **受控组件自动化测试**：无头环境下 `t-checkbox` / `t-dialog` 确认按钮难用合成事件驱动，端到端建议用 Playwright 真浏览器。
4. **API 路径写全 `/api`**：遗漏会返回 HTML 而非 JSON，典型报错「响应体格式不符合统一响应规范」。

## 九、类型与后端对齐

- `frontend/src/types/` 放跨模块 TS 类型；字段命名与后端 DTO 严格一致（如 `created_at`、`is_locked`）。
- 后端可空文本列（如 `email`）下发空串，前端无需再判 `null`；时间字段后端可空下发时前端渲染为 `-`。
- 分页响应固定 `{ list, total, page, page_size }`（见 `request.ts` 的 `PageData<T>`）。

## 十、批量导出（D7）：状态过滤用 `status_code`，不是 `status`

`BatchActionBar` + `api/business/batch.ts` 是八个列表页共用的「批量导出」入口，payload 只有三个键：

```json
{ "ids": ["…"], "keyword": "IN-2026", "status_code": "POSTED" }
```

- **`status_code`（文本码）**：ERP 单据（`erp.stock_in` / `erp.payable` / `erp.voucher`）的唯一状态过滤字段，
  值与列表页 `filter.status` **同一个值域**（后端白名单就是导出列里那份 `EnumItem`，见
  `backend/src/business/impexp/builtin/erp_doc.rs::status_codes()`），不区分大小写。
- **`status`（整型 1 启用 / 0 停用）**：只给 `system.dict_item` / `system.user` 这类开关型状态。
  **给 ERP 单据传 `status` 会 422 + 10001**（消息提示改用 `status_code`），所以三张单据页永远不传它。
- 空筛选 = **整键缺席**（不是 `status_code: ''`）。三页统一用 `@/utils/batch-action` 的
  `exportFilterPayload({ keyword, statusCode })` 拼，别各写各的 —— 漏掉一次就是「导出当前筛选结果」没按状态筛。

新增单据页要接批量导出时，照抄任一张 ERP 页的 `runBatchAction`：

```ts
return xxxBatchExport({
  ids,
  ...exportFilterPayload({ keyword: filter.xxx_no, statusCode: filter.status }),
});
```

漂移守卫在 `frontend/tests/unit/impexp-export-status-code.test.ts`：前端三份状态下拉的可选码必须**逐字等于**
后端 `erp_doc.rs` 的三张白名单，任何一侧加/删状态而另一侧没跟上，单测立刻红。

### 11.1 五文件骨架（新增一个 HR 页面照抄）

占位符与后端指南 §17.9.1 一致：`<your_domain>`（kebab，如 `certificate`）、`<YourEntity>`（Pascal，
如 `Certificate`）、`<your_perm>`（`business:hr:<your_domain>:xxx`）。

一个页面 = **五个文件**，缺一个就有一类 bug 找不到家：

| 文件 | 作用 | 铁律 |
|---|---|---|
| `src/api/business/hr/<your_domain>-kinds.ts` | 出参键名 + 码值→中文表 + 纯函数 | **不 import 请求层、不 import Vue**（`tsx --test` 能直接 import） |
| `src/api/business/hr/<your_domain>.ts` | 请求函数 | 路径**写全** `/api/...`；末尾 `export * from './<your_domain>-kinds'` |
| `src/views/business/hr/<your_domain>/index.vue` | 列表 + 筛选 + 抽屉表单 | 金额按字符串 Decimal；每个可点元素带 `data-testid` |
| `src/router/index.ts` | 路由注册 | `meta.permission` = **页面码** `business:hr:<your_domain>:page` |
| `tests/unit/hr-<your_domain>-page.test.ts` | 词表对拍 + 接线断言 | `readFileSync` 读后端 `.rs` 逐值对拍 |

**① `kinds.ts`（纯逻辑，最先写）**

```ts
/**
 * <业务名>的出参契约与词表（ARCH-9 §5.2 / §6.1）。

 * 纯逻辑文件：**不 import 请求层、不 import Vue** —— `tests/unit/hr-<your_domain>-page.test.ts`
 * 会 `readFileSync` 后端 `backend/src/business/hr/<your_domain>_dto.rs`，把下面两张表逐值对拍。
 */

/** 状态域（与 DDL 的 ck_biz_<your_table>_status 逐字一致） */
export const STATUS_VALUES = ['ACTIVE', 'EXPIRED', 'REVOKED'] as const;
export type Status = (typeof STATUS_VALUES)[number];

/** 码值 → 中文（与后端 `<your_domain>_dto.rs` 的 STATUS_LABELS 逐值一致） */
export const STATUS_LABELS: Record<Status, string> = {
  ACTIVE: '有效',
  EXPIRED: '已到期',
  REVOKED: '已注销',
};

/** 列表行（键名逐条抄后端 `*ListRes`，不缩写） */
export interface <YourEntity>ListRow {
  id: string;
  employee_id: string;
  /** 员工姓名：后端实时 join 下发（主数据改名后显示新名） */
  employee_name: string;
  no: string;
  status: Status;
  status_label: string;

/** 权限码表（与 `sys_menu.auth_code` 逐字一致；`page` 只判路由显形，其余判动作） */

  list: 'business:hr:<your_domain>:list',
```

**② `<your_domain>.ts`（请求层，路径写全 `/api`）**

```ts
/** <业务名> API 层（ARCH-9 §5.2）。后端：backend/src/business/hr/<your_domain>_handler.rs。 */
import { get, post, put, del, type PageData } from '@/api/request';
import type { <YourEntity>ListRow } from './<your_domain>-kinds';

export * from './<your_domain>-kinds';

/** 后端注解不含 `/api`（`[router].prefix` 注入）；漏了会命中 SPA fallback 返回 HTML → 「响应体格式不符合」 */
const BASE = '/api/business/hr/<your_domain>';

/** 列表（后端分页包装 `PageData<T>`：字段是 `list` / `total` / `page` / `page_size`） */
export const fetch<YourEntity>Page = (params: Record<string, unknown>) =>
  get<PageData<<YourEntity>ListRow>>(`${BASE}/page`, params);

/** 详情 */
export const fetch<YourEntity> = (id: string) => get<<YourEntity>ListRow>(`${BASE}/${id}`);

/** 新建（编号留空 ⇒ 后端取号） */
export const create<YourEntity> = (body: Record<string, unknown>) =>
  post<{ id: string }>(BASE, body);

/** 修改 / 软删 */
export const update<YourEntity> = (id: string, body: Record<string, unknown>) =>
  put<{ id: string }>(`${BASE}/${id}`, body);
export const remove<YourEntity> = (id: string) => del<void>(`${BASE}/${id}`);
```

```vue
<script setup lang="ts">
import { onMounted, reactive, ref, computed } from 'vue';
import { useUserStore } from '@/stores/user';                  // 权限判据的唯一来源（Pinia）
import {
  CERT_COLUMNS as columns, CERT_PERMS, STATUS_LABELS, STATUS_VALUES, emptyFilter,
  type <YourEntity>Filter, type <YourEntity>ListRow,
} from '@/api/business/hr/<your_domain>';
import { fetch<YourEntity>Page, create<YourEntity>, update<YourEntity>, remove<YourEntity> } from '@/api/business/hr/<your_domain>';

/** 页面显形码在路由 `meta.permission`（决定「进不进得来」），
 *  按钮判据用**接口码**（决定「这个动作做不做得了」）—— 两者已解耦（编码规范 §1.7.2）。
 *  判据一律走 `userStore.hasPermission(...)`，本仓**没有** `usePermission` 组合式函数。 */
const userStore = useUserStore();
const canCreate = computed(() => userStore.hasPermission(CERT_PERMS.create));
const canUpdate = computed(() => userStore.hasPermission(CERT_PERMS.update));
const canDelete = computed(() => userStore.hasPermission(CERT_PERMS.delete));

const rows = ref<<YourEntity>ListRow[]>([]);
const total = ref(0);
const page = ref(1);
const pageSize = ref(20);
const loading = ref(false);
const loadError = ref('');

/** 分页交给 `t-table` 的 `:pagination`（本仓所有列表页都这么写：不单独放 t-pagination） */
const pagination = computed(() => ({
  current: page.value,
  pageSize: pageSize.value,
  total: total.value,
  showJumper: true,
  showPageSize: false,
}));
function handlePageChange(pageInfo: { current: number; pageSize: number }): void {
  page.value = pageInfo.current;
  if (pageInfo.pageSize && pageInfo.pageSize !== pageSize.value) {
    pageSize.value = pageInfo.pageSize;
  }
  void loadRows();
```

### 11.3 三条范式与四个真坑（新页面直接抄）

1. **契约镜像写在 `*-kinds.ts`**：`employee-kinds.ts` / `leave-kinds.ts` / `salary-kinds.ts` 里放
   出参键名、码值→中文表、上限常量与纯函数，**单测从 Rust 源码逐字对拍**（`frontend/tests/unit/hr-*.test.ts`
   里 `readFileSync` 后端 `.rs` 断言码值表一致）。后端加一个状态而前端没跟，`pnpm test:unit` 立刻红。
2. **路由 `meta.permission` 用页面码 `*:page`，不是 `*:list`**（见 `docs/编码规范.md` §1.7.2）：
   `/business/hr/leave` → `business:hr:leave:page`。**「我的 xx」tab 按有没有 `*:list` 分流**：
   有 → `/xx/page?mine=true`；没有 → `/xx/my`。别因为「有页面码」就去调全量列表接口（员工是 403，这是设计意图）。
3. **金额一律按整数分 / 字符串 Decimal 处理**（`Decimal` 后端下发字符串，`Number()` 会丢分）：
   合计、小计、对拍都用整数分累加，展示时再格式化。

**四个真踩过的坑**：

| 坑 | 现象 | 解法 |
|---|---|---|
| `t-input-number` 写回 `number` | 契约层按 `Decimal` 走字符串，`.trim()` 抛 `TypeError`，**点保存毫无反应** | 组件值用 `string \| number` + `textOf()` 归一，并加回归单测 |
| `confirm-btn-disabled` 属性 | 对话框确认键置灰不生效（如「解锁原因 <5 字」） | TDesign 要写在 `:confirm-btn.disabled` 里，**不是** `:confirm-btn-disabled` |
| 导出按钮 | 直接 `window.open` 带不上 Bearer | `fetch` + blob + `content-type` 校验，文件名只信 `filename*=` |
| 固定列 / 展开行 | 明细展开后拿不到行数据 | 用 `#expandedRow` 插槽 + `:expand-icon`，别按行索引猜 |
