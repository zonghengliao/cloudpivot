## 验收 2：两个独立进程并发认领，同一条任务只被认领一次

做法：先停掉实例（否则每 5 s 的 cron 会抢先），库里只留一条 `PENDING` 任务，
然后起**两个操作系统进程**（同一个测试二进制的两次独立执行），用 `A4_CLAIM_AT`
（Unix 毫秒）做墙钟屏障，让两边在同一毫秒级别发认领。

```
--- 认领前 DB 状态:
EXP-A4CLAIM-0001 status=PENDING locked_by=NULL attempt=0
屏障时刻(Unix ms): 1793191294417
--- 进程 A 日志:
  [worker-A-pid479261] NO_TASK 被另一进程抢先认领 elapsed_ms=5
--- 进程 B 日志:
  [worker-B-pid479261-b] CLAIMED task_id=11111111-…-555555555555 task_no=EXP-A4CLAIM-0001 elapsed_ms=6
认领成功进程数=1   被抢先（NO_TASK）进程数=1
--- 认领后 DB 状态:
EXP-A4CLAIM-0001 status=RUNNING locked_by=worker-B-pid479261-b attempt=0 progress=0
```

- 两个进程都在 5–6 ms 内返回：B 拿到任务，A 的 `SKIP LOCKED` 直接跳过（**不是等锁**，没有阻塞）。
- `locked_by` 只记录赢家，`attempt_count` 仍是 0（认领不算一次尝试）。

## 验收 3：僵尸任务回收（RUNNING + 心跳超 30 分钟 → 回收）

做法：把一条任务手工置成「`RUNNING` + `locked_by=ghost-worker` + 心跳在 31 分钟前 + progress=60」，
再跑一次清理任务的回收函数（cron 幂等、可直调）。

```
回收前: status=RUNNING locked_by=Some("ghost-worker") progress=60 attempt=0/3 heartbeat=Some("2026-10-28 20:10:30.12834+08")
回收结果: task_no=EXP20261028-88F5 status=PENDING attempt=1/3 previous_worker=Some("ghost-worker") previous_heartbeat=Some("2026-10-28 20:10:30.12834+08")
回收后: status=PENDING locked_by=None progress=0 attempt=1/3 message=Some("执行进程心跳超时（僵尸任务回收），已重新排队")
```

同批集成用例还覆盖了三条边界：

| 用例 | 断言 |
|------|------|
| `zombie_reclaim_marks_failed_when_attempts_exhausted` | 回收也算一次尝试：`attempt_count+1 >= max_attempts` 时直接 `FAILED`（避免崩溃循环） |
| `fresh_running_task_is_not_reclaimed` | 心跳新鲜（刚刷过）的任务**不会**被回收，即使它已经跑了 2 小时 |
| `failure_schedules_backoff_and_stays_pending` | 首次失败回 `PENDING` 且 `next_run_at` 在未来 29 s（退避 30 s 生效） |

## 验收 4：产物 TTL=1 分钟，过期后下载返回 410

```
expire_at = 2026-10-28 20:42:50.779724+08（TTL=60 秒）
等待 61s 直到产物过期...
过期后下载 HTTP 状态: 410
{"code":60016,"msg":"导出结果已过期（可下载时间已结束），请重新发起导出"}
下载命中过期后的任务状态: EXPIRED
过期后的 file_path: (已清空)
过期后物理文件已删除
```

- **HTTP 410**（不是 404/409），业务码 `60016 EXPORT_EXPIRED`。
- 下载接口做「懒过期」：状态还是 `SUCCESS` 但 `expire_at` 已过 → 直接 410 并顺手置
  `EXPIRED`、删文件（不必等每天 04:40 的清理任务）。
- 清理任务侧的过期回收（`expire_artifacts`）由集成测试 `expired_artifact_file_is_purged` 覆盖：
  `file_deleted=true`、`status=EXPIRED`、`file_path=None`。

## 附加：RUNNING 期间取消（批次边界中止）

```
取消时状态=RUNNING 进度=5%
取消接口 HTTP: 200
{"code":0,"data":{"status":"RUNNING","message":"已打上取消标记，后台任务会在当前分块结束后中止"}}
取消后终态: CANCELED
取消原因: 用户取消（已在批次边界中止）
取消时进度: 10%（不是 100，说明真的中止了）
取消任务的产物路径: (无产物)
```

`PENDING` 是直接置 `CANCELED`；`RUNNING` 只打标记，worker 在**分块边界**读一次标记后自行中止，
不跨线程强杀（避免写坏半成品），也不留产物。

## 实测踩到并修掉的两个坑

1. **`? * INTERVAL '1 second'` 绑整数参数必挂**：PG 把参数推断成 `double precision`，
   驱动按整数编码 → `column "next_run_at" is of type timestamp with time zone but expression is of type text`
   / `error serializing parameter`。改为**在应用侧算好时间点**再作为 `timestamptz` 绑定
   （`finish_export_success` / `fail_export_task` / `reclaim_stale` / `purge_import_files` 四处）。
2. **A3 的导出定义 `after_id` 绑的是字符串**（`?::uuid` 位置传 `Value::Text`）：
   第 1 页正常、第 2 页必挂，10 万行导出永远停在 5%。已在 `2c59f97` 单独修（先 `Uuid::parse_str`）。

## 复现方式

```bash
# 1) 建隔离构建（不动共享工作区）
git clone /opt/git/cloudpivot.git /root/a4-build && cd /root/a4-build/backend
export PATH=/root/.cargo/bin:$PATH CARGO_TARGET_DIR=/root/a4-target
cargo build && cargo test --test impexp_worker --no-run

# 2) 灌 10 万行
cp tests/impexp/a4_seed_100k.sql /tmp/ && chmod 644 /tmp/a4_seed_100k.sql
su - postgres -c "psql -d cloudpivot_test -f /tmp/a4_seed_100k.sql"

# 3) 验收 2（不需要实例运行）
set -a; . /etc/cloudpivot/cloudpivot-test.env; set +a
export A4_DB_URL="postgres://$ALUN_DATABASE_USER:$ALUN_DATABASE_PASSWORD@$ALUN_DATABASE_HOST:$ALUN_DATABASE_PORT/$ALUN_DATABASE_NAME"
bash tests/impexp/verify_a4_claim.sh

# 4) 验收 3（真实 PG 集成测试）
BIN=$(ls -t $CARGO_TARGET_DIR/debug/deps/impexp_worker-* | grep -v '\.d$' | head -1)
$BIN --nocapture --test-threads=1

# 5) 起实例（TTL=60s）后跑验收 1/4 + 取消
export ALUN_PROFILE=test ALUN_SERVER_LISTEN=127.0.0.1:18081
export CLOUDPIVOT_IMPEXP_EXPORT_TTL_SECONDS=60
setsid nohup $CARGO_TARGET_DIR/debug/cloudpivot > /tmp/a4/server.log 2>&1 < /dev/null &
PORT=18081 bash tests/impexp/verify_a4_worker.sh
```
